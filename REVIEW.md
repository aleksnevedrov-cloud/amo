# REVIEW.md — правила ревью для этого репозитория

Применяются и к ревью Claude, и к ревью человека. Основа — `docs/security-review.md`.

## Уровни риска

| Уровень | Что затронуто | Кто проверяет | Условие слияния |
|---|---|---|---|
| **Критический** | `packages/amo/src/{oauth,token-service,salesbot,disposable-token}.ts`; `packages/shared/src/{crypto,pii,env}.ts`; `packages/db/migrations/**`, `packages/db/src/{tokens,settings}.ts`; `packages/agent/src/{factcheck,prompt}.ts`; маршруты `apps/api/src/routes/**` (авторизация, purge); `.github/**`; `Dockerfile`, `docker-compose.yml`; `scripts/check-secrets.mjs`; зависимости (`package.json`, `pnpm-lock.yaml`) | **Человек** (владелец репозитория) + ревью Claude | Одобрение человека, зелёный CI, описан откат |
| **Средний** | остальной код `packages/**`, `apps/**` с изменением поведения | Claude, человек выборочно | Зелёный CI, замечания Claude закрыты |
| **Низкий** | `docs/**`, `*.md`, тесты без правки кода, `evals/**` (кроме `run.ts`), стили и тексты виджета | Claude | Зелёный CI |

Если PR затрагивает файлы разных уровней — действует высший. Сомнение — считать уровнем выше.

## Что искать в каждом PR

1. **Изоляция аккаунтов.** Любой запрос к БД без фильтра `account_id`; `account_id` из тела запроса вместо токена.
2. **Секреты и ПДн.** Ключи, токены, пароли в коде, тестах, логах, фикстурах; телефон/e-mail/ФИО в промпте, логе или ответе API без маскирования; файлы дампов (`dump.rdb`) и `.env*` в git.
3. **Аутентификация.** Новый маршрут без проверки токена/подписи; ослабление проверки `aud`/`exp`; сравнение секретов не за константное время.
4. **SSRF и ввод.** Запрос по внешнему URL мимо `assertPublicUrl`; нет лимита размера; `return_url` не из домена amo.
5. **Промпт-инъекции и факты.** Ослабление `factcheck`; данные клиента попадают в системный промпт как инструкции; цена/срок не из результатов инструментов.
6. **Конкурентность.** Обновление refresh-токена без блокировки; повторная обработка одного сообщения; потеря идемпотентности в очереди BullMQ.
7. **Миграции.** Правка существующей миграции; необратимое удаление данных; блокирующие операции на больших таблицах.
8. **Тесты.** Поведение изменено, теста нет; тест отключён (`skip`, `only`); тест проверяет не то, что заявлено.
9. **Зависимости.** Новая зависимость без обоснования; изменение lock-файла без изменения `package.json`.
10. **Откат.** Можно ли откатить PR без ручной правки данных; что делать с применённой миграцией.

## Формат замечаний Claude

Каждое замечание: файл и строка → уровень (блокирующее / важное / мелочь) → что не так → как исправить. Без пересказа diff и без похвалы. Если замечаний нет — одна строка: «Замечаний нет», и что проверено.

## Чего не делать при ревью

- Не предлагать переписывание стиля, не относящееся к изменению.
- Не считать зелёный CI доказательством безопасности: проверки не покрывают авторизацию и изоляцию аккаунтов целиком.
- Не одобрять критический PR от имени человека: итоговое решение за владельцем.
