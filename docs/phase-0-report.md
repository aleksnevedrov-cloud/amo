## Что сверить с документацией amo при установке (п. 0.3 ТЗ)

Сайт документации amo (amocrm.ru/developers) закрыт из среды разработки. Сверено по
официальной библиотеке `amocrm/amocrm-api-php` и официальному примеру виджета Kommo:
формат одноразового токена виджета, OAuth-запросы, структура архива, размеры логотипов.

Нужно подтвердить на живом аккаунте:

1. **Хук отключения**: параметры `account_id`, `client_uuid`, `signature` и алгоритм
   `HMAC-SHA256(client_uuid|account_id, client_secret)`. Если формат другой, amo получит 401,
   а токены останутся в БД до ручного удаления.
2. **`advanced_settings`**: блок `"advanced": {"title": …}` в манифесте и колбэк `advancedSettings`,
   контейнер `#work-area-<код виджета>`.
3. **`$authorizedAjax`**: принимает параметры в стиле `$.ajax` (`url`, `method`/`type`, `data`, `contentType`).

- Сборка Docker-образа: в среде нет Docker-демона. Шаг `pnpm deploy`, на котором держится
  образ, проверен отдельно: API из production-раскладки запускается и отвечает на `/health`.
