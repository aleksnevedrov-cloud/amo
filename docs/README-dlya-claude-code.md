## С чего начать

Этап 1 из главного ТЗ: общий каркас packages/core, переименование пакетов,
pnpm-workspace. Поведение не меняется, только пути и имена.

Перед началом показать заказчику план этапа с цифрами: сколько файлов переезжает,
сколько импортов правится.

## Как работать

| Правило | Детали |
| --- | --- |
| Один этап - один коммит | в сообщении указать число добавленных и удалённых строк |
| Ветки | работать в ветке, не писать прямо в основную |
| Перед push | git fetch и rebase |
| Push и деплой | делает заказчик (/root/push.sh), в конце этапа дать список команд |
| Отчёты | данные таблицами, id всегда вместе с названием, кратко и по делу |
| Язык | русский, в том числе комментарии в коде |

## Чего не делать никогда

1. Не менять поведение розницы в переписке с клиентами.
2. Не трогать триггеры Salesbot, почту агента, парсер форм, вебхуки Wazzup.
3. Не трогать фиды Яндекс 'Товары и цены' 4375722, 4865958, 4865959.
4. Не менять боевые данные напрямую в Postgres.
5. Ничего не удалять до дампа БД и подтверждения заказчика.
6. Не переходить к этапу 6 без письменного 'опт работает'.

## Главное в двух строках

'Агент опт' делает только коммерческие предложения и ни с кем не общается:
ни в чатах, ни по почте. Его единственный вход - кнопка 'Собрать КП' в карточке сделки,
его единственный выход - файл КП и примечание в той же сделке. Отправляет менеджер сам.
