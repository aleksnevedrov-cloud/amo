## 1. Решение заказчика

Делаем два независимых продукта, а не один с двумя режимами.

| Продукт | Что делает | Статус |
| --- | --- | --- |
| Агент розница | переписка с клиентами, задачи менеджерам, база знаний, каталог | существующий агент, переименовывается |
| Агент опт | запросы КП, разбор спецификаций, поиск рыночных цен, сборка коммерческого предложения | новый |

Разделяем на всех трёх уровнях: виджеты в amoCRM, папки и процессы на сервере,
папки в репозитории. Память на сервере заказчик добавляет.

Порядок жёсткий: СНАЧАЛА собираем и запускаем 'Агент опт', беря нужное
из существующего агента, и только после его работы чистим розницу.
До этого момента розница работает как есть и не ломается ни на минуту.

Два клона одного репозитория держатся на одной ветке и обновляются поочерёдно.

## 8. Чистка кода (требование заказчика)

Разделение - не повод размножить код. К концу работ каждая строка лежит
в одном месте, и это место очевидно по пути файла.

| Что не должно остаться | Как проверяется |
| --- | --- |
| Две копии одного файла в retail и opt | ручной просмотр + поиск одинаковых имён файлов |
| Неиспользуемые импорты и переменные | eslint без ошибок |
| Мёртвые ветки и файлы-заглушки | ручной просмотр диффа |
| Упоминания КП в рознице | grep 'kp' и 'Kp' по apps/retail-* и packages/retail/* - пусто |
| Перекрёстные импорты retail <-> opt | grep по импортам - пусто |
| Старые пути и имена пакетов @ai-door/* | grep по репозиторию - пусто |
| Закомментированный код | ручной просмотр |
| Лишние зависимости в package.json | сверка с фактическими импортами |
| Остатки на сервере: /opt/ai-door, старые образы src-api и src-worker, том maildata | удаляются на этапе 7 после переезда и дампа |

Правила:

1. Общий код живёт только в packages/core. Ни одного скопированного файла
   между розницей и оптом после этапа 6.
2. Перенос файла - git mv и правка импортов. Единственное исключение - этап 2,
   где код КП копируется, чтобы розница не встала; копия живёт до этапа 6 и сносится там.
3. Функции длиннее 80 строк при переносе разбивать.
4. Комментарии на русском, только где поведение неочевидно.
5. В каждом коммите указать число добавленных и удалённых строк.
6. Заодно: 7 ошибок eslint в wazzup-dump.ts и wazzup-dumps.ts - починить, если файл и так правится.

## 12. Запреты

1. Не менять поведение розницы в переписке с клиентами.
2. Не трогать: триггеры Salesbot, почту агента, парсер форм, приёмник вебхуков Wazzup,
   фиды Яндекс 'Товары и цены' 4375722, 4865958, 4865959.
3. Не менять боевые данные напрямую в Postgres - только через миграции и код.
4. Ничего не удалять до дампа БД и подтверждения заказчика.
5. Автоотправки КП нет.
6. Цены комплектующих - из карточки двери (door_components), общих цифр не подставлять.
7. Не выдумывать цены, остатки, сроки и сертификаты.

## 13. Расчёт цены и НДС

Правила закрыты заказчиком 12.10.2026, полный текст - docs/tz-kp-market-pricing.md, раздел 6.
Коротко: цена предложения = медиана сопоставимых конечных розничных цен x коэффициент
(по умолчанию 1,00; настраивается общий, по производителю, по позиции); наценка на закупку
не применяется; налоговый статус источника по умолчанию 'не указан'; наш НДС 22 %
считается независимо, цена предложения - уже конечная с НДС.
