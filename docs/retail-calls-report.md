### П. 0 — проверки на сервере

База сервера из сессии недоступна, поэтому цифры вносятся по результатам запросов (только чтение):

```bash
cd /opt/ai-door/src
docker compose exec db psql -U aidoor -d ai_door -c "SELECT (sent_at AT TIME ZONE 'Europe/Moscow')::date AS day, count(*) AS msgs, count(lead_id) AS with_lead, round(100.0 * count(lead_id) / count(*)) AS pct_lead, count(DISTINCT chat_id) AS chats FROM wazzup_messages WHERE sent_at >= now() - interval '14 days' GROUP BY 1 ORDER BY 1;"
docker compose exec db psql -U aidoor -d ai_door -c "SELECT source, chat_type, count(*) FROM wazzup_messages WHERE sent_at >= now() - interval '14 days' GROUP BY 1, 2 ORDER BY 3 DESC;"
```

Имя контейнера БД и пользователя — из `docker-compose.yml` розницы. Что смотреть: дни без строк — вебхуки Wazzup молчали; низкая доля `with_lead` — привязка к сделке идёт только через Salesbot (`resolveChatKind`), поэтому выборка Wazzup для итога сделана **по `lead_id` или по телефонам контактов сделки** (`chatForLeadBetween`), а не только по `lead_id`.

**Почта — источник.** Модуль `packages/retail/mail` опрашивает один IMAP-ящик аккаунта (настройки `email.*`, пароль в `mailbox_credentials`): входящие письма он кладёт в `dialog_messages` (роль `client`, текст «Тема письма: …»), исходящие — только отметку `email_outbound` без текста; тел писем менеджера нигде нет. Письма карточки amoCRM (`GET /api/v4/leads/{id}/notes?filter[note_type][]=amomail_message`) содержат оба направления с темой, текстом и названиями вложений — если ящик подключён к amo. **Выбрано:** письма карточки amo как основной источник (оба направления), входящие из IMAP (`dialog_messages`) — как дополнение; одно и то же письмо из двух источников (та же тема и направление в пределах 10 минут) считается один раз. Текст — без цитат и подписей.

## Показ итога по одной сделке (RFD-AI-AGENT-CALLS-DEMO)

```bash
cd /opt/ai-door/src && docker compose exec worker node apps/worker/dist/calls-demo.js --lead <id сделки> [--date ГГГГ-ММ-ДД] [--post]
```

Звонки сделки и её контактов за день (по умолчанию — день последнего звонка с записью; короче `minDurationSec` не берутся), скачивание, расшифровка асинхронным SpeechKit с ожиданием до 5 минут, итог тем же кодом, что `calls-day-summary` (`analyzeGroup`). ### П. 0 — как сейчас разбираются вложения почты

| | Как устроено |
|---|---|
| Где | `packages/retail/mail/src/poller.ts` (IMAP-опрос) → `DocumentService.analyze` (`packages/core/docs/src/service.ts`) → `saveMailAttachments` (`packages/retail/mail/src/attachments.ts`) |

| Пункт ТЗ | Реализация |
|---|---|
| 1. Разбор файлов в обе стороны | Миграция `020_wazzup_files.sql`: в `wazzup_messages` поля `file_name`, `file_text`, `file_status` (done / skipped / failed), `file_error`, `file_extracted_at` + частичный индекс по неразобранным. ### Стоимость разбора файла

| Составляющая | Оценка |
|---|---|
| Извлечение текста PDF / DOCX / XLSX | бесплатно (на сервере) |
| OCR скана или фото (Yandex Vision) | по тарифу Vision, порядка 0,1 ₽ за страницу / картинку; Tesseract — бесплатно |
| Разбор моделью (маршрут агента) | 3–10 тыс. входных токенов + до 2 тыс. выходных; на модели агента ≈ $0,02–0,05 (2–5 ₽) за документ, фото с текстом — столько же плюс OCR |
| Итого | обычный КП в PDF — 2–5 ₽; при объёме сервера (за 14 дней 75 документов и 223 картинки в обе стороны) — порядка 20 файлов в день, ≈ 50–100 ₽ в день |

Фактическая стоимость каждого файла пишется в `ai_journal` (kind `document`, `cost_usd` / `cost_rub`): `SELECT created_at, summary, cost_rub FROM ai_journal WHERE kind = 'document' AND summary LIKE 'Разобран файл Wazzup%' ORDER BY created_at DESC LIMIT 20;`. Расход ограничен `vision.maxFilesPerDay` (общий лимит с почтой и входящими файлами). Старые входящие файлы, уже разобранные агентом при получении, повторно не разбираются (помечаются «разобран агентом при получении»), а все прежние исходящие документы и картинки менеджера за историю будут разобраны фоновым заданием по 20 за проход — это разовый расход.

## Исправление RFD-AI-AGENT-CALLS-DEMO-SOURCES: показ по сделке без звонков давал «записей ленты 0»

Звонки включены по умолчанию (`callsEnabled: true`): после развёртывания первый опрос соберёт звонки с момента включения (историю не тянет), в 19:30 МСК — первый итог дня. Выключить: `PUT /widget/v1/settings` с `calls.callsEnabled: false`.

Догрузка за 30 дней (сначала оценка, потом запуск):
```bash
cd /opt/ai-door/src
docker compose exec worker node apps/worker/dist/calls-backfill.js --days 30
docker compose exec worker node apps/worker/dist/calls-backfill.js --days 30 --yes
```

Откат розницы: `git checkout 616062b`, пересобрать api и worker. Таблицы 018 остаются. Если настройки сохраняли после развёртывания — в них появился блок `calls`, строгая схема прежнего кода его не примет: перед откатом сохранить настройки без него (`PUT` без ключа `calls` на старом коде невозможен — поэтому откат кода лучше делать до первого сохранения настроек, иначе — удалить ключ из `widget_settings` вручную после дампа).
