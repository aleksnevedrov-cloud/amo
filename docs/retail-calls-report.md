## Что сделано по пунктам ТЗ

| Пункт | Сделано |
|---|---|
| **1. В течение дня** | Очередь `calls` в воркере розницы (отдельно от `maintenance`, чтобы не задерживать почту и задачи), задание `calls-poll` раз в 10 минут: примечания call_in / call_out контактов и сделок с отметки, дедупликация, привязка к открытой сделке контакта в воронке «Двери» (самая свежая), скачивание, расшифровка (асинхронный SpeechKit, ожидание до 30 с в опросе; отложенный — без ожидания), пул на 2 звонка, удаление MP3 по сроку (30 дн.). Короче `minDurationSec` (30 с), без записи и с пустой расшифровкой — `unavailable` с причиной. После расшифровки — `transcribed`, примечание не пишется. |
| **2. Итог дня** | Задание `calls-day-summary`: проверка раз в 5 минут, запуск, когда по Москве наступило `calls.daySummaryTime` (19:30) и сегодня ещё не запускали (отметка в `calls_sync`, entity `day_summary`). Нерасшифрованные ждут до `daySummaryTimeoutSec` (300 с, с проверкой операций SpeechKit каждые 15 с); не успели — в итог следующего дня с пометкой даты звонка в заголовке. Сделки — по id из amo пачками по 50: только воронка `pipelineId` (1873498), этапы не 142 / 143 и из `statusIds` (пусто — все); остальные — `analyzed` с причиной, в итог не входят. Без сделки — группа по контакту. На группу — один вызов модели (строгий JSON: summary, agreements, nextStep, managerScore, managerComment, callsCount, totalDuration, callIds, speakers; повтор при ответе не по схеме; `callsCount` и `totalDuration` пересчитываются по входу). Звонки не из `callIds` (без делового содержания) — `analyzed`; деловых нет — примечания нет, итог сохраняется с `business = false`. Ошибка по группе не останавливает остальные (пул на 2 группы), лимита на число сделок нет. Критерии оценки — п. 2 ТЗ (тип двери, количество, размеры, покрытие, опт/розница, бюджет, сроки, замер, доставка и монтаж; следующий шаг со сроком; вежливость). |
| **3. Примечание** | Одно `common` в сделку (без сделки — в контакт) по формату ТЗ, дата в заголовке — день звонков. Таблица `call_day_summaries` (account, lead / contact, day, summary, note_id, call_ids, стоимость); звонки итога — `posted` (с примечанием) или `analyzed`, со ссылкой `day_summary_id`. Дубли: вошедшие в итог звонки больше не берутся; повторный запуск в тот же день пишет отдельный итог только по новым звонкам. Задачи не ставятся. |
| **4. Вечерний обход** | `sweepDeps.callTexts` читает последний деловой итог за день по сделке из `call_day_summaries` (своя БД, без сети) → «Итог: …», «Следующий шаг: …». `buildComment` всегда добавляет отдельной строкой блок «Разговоры за день: …» или «За сегодня разговоров в сделке не было.» (переписка — как раньше, до 700 знаков; весь комментарий — до 900). `ensureTask`, `maxPerRun` и этапы обхода не менялись; итог дня делается отдельным заданием независимо от задач. |
| **5. Догрузка** | `calls-backfill.js --days N`: без `--yes` — по аккаунту: примечаний найдено, новых с записью (минуты), будущих примечаний (сделка / контакт × день), оценка расшифровки в отложенном режиме и итогов моделью; ничего не пишет. С `--yes` — сбор и скачивание (до 1000 за запуск), режим `deferred`; расшифровку делает `calls-poll`, итоги по дням — ближайший запуск итога дня: звонки старше вчерашнего группируются по своему дню, заголовок — с фактической датой. Записи, которые ВАТС не отдаёт, — `unavailable` без повторов. |
| **6. Ошибки** | Шаг упал → `failed` + `stage` + `ai_journal` (`call_error`), `attempts + 1`; повтор не раньше чем через 30 мин, не больше 3 попыток, затем один алерт в Telegram (`TelegramAlerter`, без токена — тихо). Для итога дня — то же по звонкам группы (stage `day`). Итог задания — запись `call_day_run`: «сделок и контактов N, звонков M, примечаний K, без делового содержания, вне воронки или этапа, ошибок, не дождались расшифровки». |
| **7. Настройки** | Блок `calls`: `callsEnabled` true, `postDayNote` true, `daySummaryTime` «19:30», `daySummaryTimeoutSec` 300, `pipelineId` 1873498, `statusIds` [] (все, кроме 142 / 143), `minDurationSec` 30, `keepMp3Days` 30, `sttProvider` speechkit (запасной openai). Схема строгая с умолчаниями: старые сохранённые настройки читаются; экрана в виджете нет — правка через `PUT /widget/v1/settings`. |

```
Итог разговоров за 22.10.2026: 3 звонка, общая длительность 9:15
Итог: Клиенту нужны три межкомнатные двери, замер на неделе.
Договорённости: 
— Замер в четверг 23.10
— Менеджер пришлёт расчёт после замера
Следующий шаг: Менеджер согласует время замера.
Оценка менеджера: 8/10 — Потребность и сроки выявлены, бюджет не уточнил.
```

Одна договорённость — в строку; нет — «Договорённости: нет», «Следующий шаг: не определён». Звонок прошлого дня, не успевший расшифроваться: «…общая длительность 6:10 (в т. ч. звонки от 22.10)».

## Стоимость

Минута звонка (с НДС, тарифы сверены): SpeechKit асинхронный режим 0,1515 ₽ / 15 с = **0,606 ₽/мин**; отложенный режим 0,0381 ₽ / 15 с = **0,1524 ₽/мин**; тарификация блоками по 15 с (так же считает код и оценка догрузки). OpenAI (запасной) — $0,006/мин.

Итог на сделку — один вызов модели на все звонки дня: ≈ 1 200 токенов подсказки + ≈ 230 токенов на минуту разговора на входе, ≈ 450 на выходе. По модели розницы по умолчанию (`anthropic:claude-opus-5`, тарифная таблица проекта, курс 90 ₽/$):

| Сделка за день | Итог моделью | Расшифровка, асинхронно | Расшифровка, отложенно | Всего (асинхронно / отложенно) |
|---|---|---|---|---|
| 1 звонок, 3 мин | $0,0207 ≈ 1,86 ₽ | 1,82 ₽ | 0,46 ₽ | 3,68 ₽ / 2,32 ₽ |
| 3 звонка, 9 мин | $0,0276 ≈ 2,48 ₽ | 5,45 ₽ | 1,37 ₽ | 7,93 ₽ / 3,85 ₽ |
| 5 звонков, 20 мин | $0,0403 ≈ 3,62 ₽ | 12,12 ₽ | 3,05 ₽ | 15,74 ₽ / 6,67 ₽ |

Фактические суммы по каждому итогу — в `call_day_summaries.cost` и в журнале `call_day`; по звонку — в `calls.cost`.

## Проверка ролей говорящих (п. 8)

Поле метки говорящего в ответе SpeechKit документацией не подтверждено (парсер берёт `speakerTag`, иначе `channelTag`). После первого расшифрованного звонка — до догрузки:

```bash
cd /opt/ai-door/src && docker compose exec worker node apps/worker/dist/calls-inspect.js
```

Печатает первые 10 реплик с метками (и ролями, если итог уже был) и начало `transcript.rawSample`. Если у всех реплик «говорящий —» — по сырому ответу видно настоящее поле, правка в одну строку в `parseSpeechKitLines` (`packages/core/calls/src/stt.ts`).

## Развёртывание

Розница (миграция 018 применится при старте api):
```bash
cd /opt/ai-door/src; git fetch origin claude/new-session-8uzdox && git checkout <хеш> && docker compose build api worker && docker compose up -d api worker
docker compose logs --since 2m worker | grep -i "calls\|worker запущен"
```

Опт (calls-poll отключён):
```bash
cd /opt/agent-opt; git -C src fetch origin claude/opt-kb && git -C src checkout 5ae7ce5 && docker compose build opt-api opt-worker && docker compose up -d opt-api opt-worker
```

Переменные `.env` розницы (`/opt/ai-door/.env`):
- `YANDEX_SPEECHKIT_API_KEY`, `YANDEX_FOLDER_ID` — ключи SpeechKit (если нет — внести; без них расшифровка пойдёт через `OPENAI_API_KEY`);
- `NO_PROXY=.megapbx.ru,.onpbx.ru` — по ТЗ; в образе Node 22 глобальный `fetch` переменные прокси не читает, запросы к ВАТС и так идут напрямую (переменная безвредна);
- `TELEGRAM_ALERT_BOT_TOKEN`, `TELEGRAM_ALERT_CHAT_ID` — для алертов (уже есть);
- `MAIL_FILES_ROOT` — корень файлов (по умолчанию `/data`, том `maildata`); записи — `/data/calls/<аккаунт>/<год-месяц>/`.

Звонки включены по умолчанию (`callsEnabled: true`): после развёртывания первый опрос соберёт звонки с момента включения (историю не тянет), в 19:30 МСК — первый итог дня. Выключить: `PUT /widget/v1/settings` с `calls.callsEnabled: false`.

Догрузка за 30 дней (сначала оценка, потом запуск):
```bash
cd /opt/ai-door/src
docker compose exec worker node apps/worker/dist/calls-backfill.js --days 30
docker compose exec worker node apps/worker/dist/calls-backfill.js --days 30 --yes
```

Откат розницы: `git checkout 616062b`, пересобрать api и worker. Таблицы 018 остаются. Если настройки сохраняли после развёртывания — в них появился блок `calls`, строгая схема прежнего кода его не примет: перед откатом сохранить настройки без него (`PUT` без ключа `calls` на старом коде невозможен — поэтому откат кода лучше делать до первого сохранения настроек, иначе — удалить ключ из `widget_settings` вручную после дампа).
