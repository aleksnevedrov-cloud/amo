# Догон клиента после отказа (RFD-AI-AGENT-REAKTIVATSIYA)

Агент сам пишет клиенту, который ушёл в «Отказ»: два касания за неделю, затем молчит навсегда.
Правила согласованы владельцем аккаунта 30.10.2026.

## Правила

Отбор:
- воронка «Двери» (1873498), этап «Закрыто и не реализовано» (143);
- отказ не старше 14 дней;
- бюджет сделки (поле «Бюджет» amoCRM) не ниже 30 000 ₽;
- каналы: WhatsApp (бот-отправщик Salesbot) и письмо тем же текстом.

Касания: № 1 — на 2-й день от перехода в отказ, № 2 — на 5-й. После второго не писать никогда.

**Исключение — причина отказа «купил у конкурента».** Двери у клиента уже есть, продавать нечего:
вместо двух касаний уходит одно сообщение — шаблон «Отказ» (опрос отдела качества: причина и какого
поставщика выбрал), и догон закрывается. Ответ клиента на него ложится примечанием, агент не отвечает.
Наборов текстов поэтому четыре, а не пять: дорого, нет в наличии, передумал, универсальный.

Ответ клиента — агент замолкает, дальше либо менеджер, либо шаблон «Отказ»:

| Ответ клиента | Что делает агент | Этап сделки |
|---|---|---|
| Интерес, вопрос, что-либо неоднозначное | задача ответственному, сам не отвечает | → «Заказ» |
| «Подумаю» и назван срок | задача менеджеру, срок — словами клиента | → «Заказ» |
| «Подумаю» без срока | напомнит сам через 7 дней — последнее касание | «Отказ» |
| Отказ повторно | шаблон «Отказ» (опрос отдела качества) в WhatsApp и письмом, стоп | «Отказ» |
| Ответ на шаблон «Отказ» | примечание в сделку, **агент не комментирует** | «Отказ» |
| Менеджер написал клиенту сам | догон прекращается | без изменений |

Перевод в «Заказ» нужен потому, что менеджеры отказы не видят — для них сделка закрыта.

## Как устроено

Свой опрос событий не нужен: переход в «Отказ» уже ловит анализ отказов
(`refusal_analyses`), догон берёт разобранные отказы — `RefusalsRepo.listAnalyzedSince`.

- `packages/retail/agent/src/reactivation.ts` — отбор (`planReactivations`), касания
  (`runTouches`), разбор ответа клиента (`handleReactivationReply`), канал отправки
  (`senderBotSend`), проход по аккаунтам (`runReactivationAll`).
- `packages/core/db/src/reactivation.ts` + миграция `025_reactivation.sql` — состояние догона,
  одна строка на сделку (уникальность по сделке: повторный отказ догон заново не начинает).
- `apps/worker/src/reactivation-deps.ts`, задание `reactivation-poll` раз в 10 минут.
- Перехват ответа клиента — в `pipeline.ts` до проверки «этап без AI»: этап «Отказ» ею помечен,
  иначе ответ на касание агент бы не увидел.

Отправка идёт ботом-отправщиком тем же путём, что одобренные черновики
(`suggestions.addApproved` + `runSalesbot`), поэтому встроенная проверка «менеджер ответил сам»
работает и для касаний. Второго пути отправки нет.

Причина отказа у модели — свободный текст, поэтому набор текстов выбирается по ключевым словам:
дорого / нет в наличии / передумал, иначе универсальный; «купил у конкурента» — отдельный сценарий выше.

Отсеянные сделки (бюджет ниже порога, уведена с «Отказа», сделки нет) записываются стоп-строкой,
чтобы отбор не дёргал их из amo каждые 10 минут. Сбой amo решения не принимает — сделка вернётся
следующим проходом.

## Запрет задач в закрытых сделках сохранён

`canCreateTask` получил флаг `reactivated`: после возврата сделки на этап заказа остаточный
`closed_at` (amo оставляет его от прежнего закрытия) не считается закрытием. Сами этап, воронка
и правило «вторая задача не ставится, если задача уже есть» проверяются как обычно; этапы
142 и 143 флаг не открывает.

## Настройки

Вкладка виджета «Догон после отказа» (виджет 1.2.4): включение, воронка, **этап «Заказ»**
(выбирается из справочника воронки), минимальный бюджет, срок давности, дни касаний, дни
напоминания, сделок за проход, дубль письмом, шаблон «Отказ» и тексты касаний по причинам.

Выключено по умолчанию (`reactivation.enabled: false`): включает владелец аккаунта, когда
проверит тексты. Нужен выбранный бот-отправщик (`salesbot.senderBotId`) — без него касания
не уходят, в журнал пишется причина.

```bash
cd /opt/ai-door/src
git fetch origin claude/new-session-j84ws6 && git checkout origin/claude/new-session-j84ws6
docker compose build api worker && docker compose up -d api worker   # миграция 025 применится при старте api
```

Виджет: `WIDGET_API_URL=https://ai.rf-dveri.ru pnpm widget:build` → `apps/widget/dist/widget.zip`
→ загрузить в amoCRM. Затем на вкладке «Догон после отказа» выбрать воронку и этап «Заказ»,
проверить тексты и включить догон.

Откат: `git checkout 6bc1bde`, пересобрать api и worker. Таблица `reactivation_leads` остаётся.
Если настройки сохраняли после развёртывания — в них появился блок `reactivation`, и строгая
схема прежнего кода его не примет: удалить ключ из `widget_settings` вручную.

## Ограничения

- Письма не уходят: порты SMTP Яндекса (465, 587) с сервера закрыты. До решения работает
  только WhatsApp; настройка «Дублировать письмом» включена и начнёт работать сама, когда
  почта заработает.
- Шаблоны Wazzup через Salesbot недоступны, поэтому текст шаблона «Отказ» хранится в настройках
  агента и совпадает с одноимённым шаблоном Wazzup. Расхождения нужно править в двух местах.

## Ревью 01.11.2026 — исправления до развёртывания

Проверка кода догона перед применением на сервере (`pnpm check` по всей ветке) нашла три ошибки,
все исправлены с тестами (`packages/retail/agent/test/reactivation.test.ts`):

1. **Напоминание после «подумаю» не отправлялось никогда.** Разбор ответа ставил `client_reply_at`
   и состояние `reminder`, а отправка касаний останавливала любую строку с `client_reply_at`
   как «клиент ответил» — раньше, чем доходила до ветки напоминания. Прежний тест подставлял строку
   без `client_reply_at` и ошибку не видел; добавлен сквозной тест: ответ «надо подумать» → через
   7 дней напоминание уходит, строка закрывается `reminder_sent`.
2. **Слово «отказ» не распознавалось как отказ.** В регулярном выражении стояла граница слова `\b`,
   которая в JavaScript работает только для латиницы: «Отказ», «отказываюсь», «отказались» уходили
   менеджеру как интерес. Граница заменена на `(?!\p{L})`.
3. **Цена с точкой считалась датой.** «за 15.000 сделаете» давало срок «15.00» и ответ шёл как
   «подумаю со сроком». Дата теперь не может быть частью большего числа.

Попутно приведены в порядок тесты, падавшие на ветке независимо от догона: три теста звонков
зависели от текущей даты (время запуска итога дня теперь передаётся в `setSync` явно, срок хранения
MP3 в тесте считается от подменённого «сейчас»), три теста API и один тест виджета отстали от кода
(справочник отдаёт `users`, бот-отправщик проверяет события чата, ответ `continue` идёт через `data`,
пароль почты уходит с `mailboxId`), 9 замечаний линтера в файлах выгрузки Wazzup и вложений.

Код слит в ветку `claude/new-session-j84ws6`; на сервер ставить её последний коммит, а не `1e905b4`.
