# Установка и настройка

## 1. Сервер

Отдельный сервер в РФ (не amo.rf-dveri.ru), Docker + Docker Compose, публичный HTTPS-домен
(например `ai-agent.rf-dveri.ru`) с обратным прокси (nginx/Caddy) на `127.0.0.1:3000`.

```bash
cp .env.example .env
openssl rand -hex 32        # → TOKEN_ENCRYPTION_KEY
# заполнить PUBLIC_URL, POSTGRES_PASSWORD, DATABASE_URL, AMO_CLIENT_ID, AMO_CLIENT_SECRET; ключи LLM — ANTHROPIC_API_KEY / OPENAI_API_KEY или в виджете
docker compose up -d --build
curl https://ai-agent.rf-dveri.ru/health   # {"status":"ok",...}
```

Миграции БД применяются автоматически при старте `api`.

## 2. Интеграция в amoCRM (aleksnevedrov)

1. «amoМаркет» → интеграция → «Редактировать».
2. **Ссылка для перенаправления:** `https://<PUBLIC_URL>/oauth/amo/callback`.
3. **Ссылка для хука об отключении:** `https://<PUBLIC_URL>/oauth/amo/disconnect`.
4. Доступ: «Доступ к данным аккаунта».
5. Загрузить архив виджета `widget.zip` (см. ниже).
6. ID интеграции и секретный ключ из «Ключи и доступы» → `.env` (`AMO_CLIENT_ID`, `AMO_CLIENT_SECRET`), перезапуск: `docker compose up -d`.
7. Установить виджет. amo вызовет redirect URI — страница ответит «Интеграция подключена».

**Где настройки.** Настройки → Интеграции → «Установленные» → карточка виджета: в модальном окне рисуется полная
форма (вкладки «Статус», «Модель», «Каталог» и т. д.) — провайдер и ключи LLM, включение агента и режим задаются здесь.
Сверху формы ссылка «Открыть настройки на всю страницу» → `/settings/widgets/<код виджета>/` (страница локации
`advanced_settings`; на живом аккаунте отдельного пункта меню для неё нет, поэтому форма продублирована в окне
интеграции). Штатная кнопка «Сохранить» в окне amo к нашим настройкам не относится — в форме своя кнопка.

amo передаёт `redirect_uri` при каждом обмене и обновлении токена, поэтому он должен совпадать с п. 2.

## 3. Архив виджета

```bash
WIDGET_API_URL=https://ai.rf-dveri.ru pnpm widget:build
# → apps/widget/dist/widget.zip (версия 1.1.0)
```

Логотипы в архиве — фирменные, нарезаны из логотипа РФ-Двери (`apps/widget/static/images/`, 130×100, 400×272,
240×84; квадратные 84×84 и 108×108 — знак «РФ»). Чтобы заменить, положите PNG тех же размеров с теми же именами.

## 4. Каталог (фиды YML)

Агент берёт цены и наличие только из каталога. У РФ-Двери каталог выгружается из UMI тремя фидами YML
(адреса из документа по антиботу от 28.09.2026):

| Фид | Адрес |
|---|---|
| Входные | `https://www.rf-dveri.ru/admin/exchange/get_export/4865958/?as_file=0` |
| Межкомнатные | `https://www.rf-dveri.ru/admin/exchange/get_export/4375722/?as_file=0` |
| Фурнитура | `https://www.rf-dveri.ru/admin/exchange/get_export/4865959/?as_file=0` |

1. Настройки виджета → «Каталог» → вставить все три адреса, по одному в строке → «Сохранить».
2. «Обновить сейчас». Фиды сливаются в один каталог; статус и число товаров видны там же. Дальше — раз в сутки.

Поддерживаются кодировки UTF-8 и windows-1251. Пустой или битый фид не затирает рабочий каталог.

**Антибот сайта rf-dveri.ru.** Бэкенд ходит на сайт за фидами и за статьями для базы знаний:
- фиды по `/admin/exchange/…` проходят по правилу `ALLOW · uri · /admin/` (таблица 5 антибота);
- бэкенд всегда представляется `User-Agent: AI-Door-Agent/1.0 (+https://rf-dveri.ru; …)` — пустой User-Agent антибот
  отправляет в STOP;
- статьи сайта для базы знаний идут через общую проверку, поэтому IP сервера бэкенда (186.246.1.169) стоит добавить
  в таблицу 1 «Table of IPv4 rules» как ALLOW — иначе вместо статьи придёт страница проверки.

## 5. База знаний

Настройки виджета → «База знаний»: FAQ (доставка, оплата, гарантия, замер, монтаж), тексты о покрытиях,
статьи по адресу (например, из раздела «Полезные советы про двери»). Сроки и стоимость услуг агент
называет только отсюда: пока их нет в базе, на такие вопросы он передаёт диалог менеджеру.

## 5а. Правила цен

Настройки виджета → «Правила цен». Здесь задаётся, как агент считает комплект:

- стандартные ширины и высоты полотна и наценка за нестандартный размер (по накладным — 30 %);
- комплектующие: сколько штук на дверь (коробка ~2,5, наличник 5), цены по сериям дверей
  (например, «Стэфани = 1224»), цена по умолчанию;
- доборы — с 0 шт. на дверь и без отметки «в комплекте»: агент добавляет их по толщине стены;
- услуги: за заказ, за дверь, за км (с базовой ценой), за дверь за этаж.

Правила можно заполнить на странице или загрузить таблицей: «Скачать XLSX» даёт шаблон с тремя листами
(«Размеры», «Комплектующие», «Услуги»), его заполняют и загружают обратно через «Загрузить XLSX».
Внизу вкладки — «Тест расчёта»: товар, размер, количество → черновик детализации.

Пока правил нет, агент не называет итоговую сумму и ставит менеджеру задачу на расчёт.
Расчёт агента — это черновик в колонках «Детализации сделки». Он появляется в панели AI и в примечании
к сделке. Скидку и НДС ставит менеджер.

## 6. Проверка в песочнице

Настройки виджета → «Песочница». Агент отвечает по вашему каталогу и базе знаний, показывает вызванные
инструменты, источники и стоимость. CRM — тестовая сделка, клиенту ничего не уходит.
Несохранённые изменения на вкладках настроек проверяются в песочнице как черновик.

## 7. Подключение к чатам: Salesbot + Digital Pipeline

1. **Salesbot:** «Настройки» → «Salesbot» → создать бота «AI-продавец». Добавить шаг «Виджеты» →
   «AI-продавец: ответить клиенту». Сохранить.
2. **Digital Pipeline:** в каждой воронке на каждом этапе, где работает AI, добавить триггер
   «Salesbot» → «При входящем сообщении» → бот «AI-продавец». По решению заказчика AI работает во всех
   воронках, круглосуточно.
3. Настройки виджета → «Статус»: включить AI, режим «Автоматический» → «Сохранить».
4. Написать в WhatsApp с тестового номера и проверить ответ. Журнал — вкладка «Журнал» и панель в карточке сделки.

**Каналы.** Salesbot работает в чатах amo: сейчас WhatsApp; Max — после подключения через Wazzup
(это будет обычный канал чатов amo, настройка та же). Почта — отдельное подключение к ящику (п. 9).

### Режим «Полуавто»: бот-отправщик

В «Полуавто» ответ AI становится черновиком: менеджер правит и одобряет его в панели сделки или на вкладке
«Черновики». Одобренный черновик уходит клиенту через второго бота:

1. Salesbot → создать бота «AI-отправщик», шаг «Виджеты» → «AI-продавец: отправить одобренный черновик». Сохранить.
2. Запомнить ID бота (виден в адресе конструктора) → настройки виджета → «Где работает» → «Бот-отправщик».
3. При одобрении бэкенд запускает этого бота по сделке через API amo, бот забирает черновик и отправляет в чат.

### Технический запрет на отправку при активном менеджере

Ограничение держится кодом, а не формулировкой в промпте. Допуск к отправке считает
`canReply` (`packages/agent/src/can-reply.ts`) и проверяется в двух точках:

| Точка | Когда | Что делает |
|---|---|---|
| `packages/agent/src/pipeline.ts`, перед `release` | каждый ответ агента | перечитывает паузу диалога и запрашивает события чата amo заново |
| `apps/api/src/routes/salesbot.ts`, ветка `kind: 'send'` | отправка одобренного черновика | смотрит сообщения менеджера только ПОСЛЕ одобрения (`decided_at`) |

Зачем вторая проверка: между проверкой в начале хода и отправкой проходит 17–31 с — окно
склейки, вызов модели (замер 30.09: 12,1 с), имитация набора. Менеджер успевает вступить
в диалог, и раньше ответ всё равно уходил клиенту.

Что происходит при запрете:

| Шаг | Результат |
|---|---|
| Клиенту | ничего не отправляется, бот просто продолжается пустым списком |
| Текст ответа | сохраняется менеджеру подсказкой в карточке сделки — не теряется |
| Журнал | `kind = blocked`, `details.reason` = `manager_active` или `paused`, плюс текст, автор сообщения менеджера и id подсказки |
| Сделка | переводится на паузу `manager_message` |

Исключения: явная передача агенту (обращение по имени в разрешённой группе) снимает запрет
по паузе, но **не** снимает запрет по активному менеджеру. Нажатие «Отправить» на черновике —
это и есть явная передача, поэтому сам факт участия менеджера отправку не запрещает; запрещает
только его сообщение клиенту после одобрения. Если amoCRM недоступна, запрет не накладывается —
иначе агент замолчал бы при любом сбое API.

### Голосовые сообщения

Настройки → «Где работает» → «Голосовые сообщения»: Yandex SpeechKit (данные в РФ) или OpenAI Whisper.
Ключи — в `.env` на сервере (`YANDEX_SPEECHKIT_API_KEY` и `YANDEX_FOLDER_ID` или `OPENAI_API_KEY`).
Чтобы голосовое дошло до бэкенда, в шаг Salesbot нужно передать ссылку на вложение
(`attachment_url`, `attachment_type`). Как получить её в Salesbot — проверяется при установке, см. отчёт фазы 2.

## 8. Приёмка фазы 1

```bash
# 30 эталонных диалогов на реальной модели (тестовый каталог и правила цен, по оценке $3–8 за прогон)
ANTHROPIC_API_KEY=... TEST_DATABASE_URL=postgres://... pnpm --filter @ai-door/evals eval

```

Отчёт сохраняется в `evals/results/`. Критерий: все диалоги пройдены, выдуманных данных — 0.

## 9. Почта

Для Яндекс Почты — пошаговая инструкция: [email-yandex.md](email-yandex.md).

AI читает ящик по IMAP и отвечает по SMTP с того же адреса. Ящик открывается **только на чтение**:
письма не помечаются прочитанными и не перемещаются, почта в amo продолжает работать как раньше.

1. В почтовом сервисе создайте **пароль для приложений** (Яндекс: «Безопасность» → «Пароли приложений»;
   Mail.ru: «Пароли для внешних приложений»; Gmail: «App passwords»). Включите доступ по IMAP.
2. Настройки виджета → «Почта»: кнопка сервиса (Яндекс / Mail.ru / Gmail) заполнит серверы; укажите логин.
3. «Сохранить пароль» — пароль хранится зашифрованным и больше не показывается.
4. Отметьте «AI отвечает на письма клиентов», задайте подпись, поведение для новых адресов и исключения
   (поставщики, сервисы, свои сотрудники) → «Сохранить».
5. «Проверить подключение» — должно быть «подключено» для IMAP и SMTP и найдена папка «Отправленные».

Как работает:

- Ящик опрашивается раз в минуту. **При первом подключении старые письма не обрабатываются** — только новые.
- **AI отвечает только клиентам в сделках**: письмо привязывается к открытой сделке контакта с этим e-mail.
  Заявки в «Неразобранном» сделкой не считаются — туда почта amo кладёт письма от кого угодно.
- Почта уже подключена к amo (вариант по умолчанию): письмо нового клиента ждёт, пока amo создаст заявку и
  менеджер примет её в работу (по умолчанию до 60 минут); тогда AI отвечает в сделке. Сам AI сделок не создаёт.
  Если почта не подключена к amo — можно создавать контакт и сделку или не отвечать (настройка).
- Ответ AI уходит в ту же цепочку («Re: тема»), копия кладётся в «Отправленные» — amo покажет её в переписке
  сделки. Дублировать примечанием не нужно (включается в настройках, если почта не подключена к amo).
- Режимы те же, что в чатах: «Авто», «Полуавто» (черновик письма уходит сразу после одобрения, бот не нужен),
  «Подсказки». Если менеджер сам ответил клиенту (письмо в «Отправленных»), AI встаёт на паузу.
- AI не отвечает на автоответы, рассылки, noreply-адреса, свои письма и адреса из исключений; не больше
  N ответов на один адрес в сутки (по умолчанию 10) — защита от переписки с автоответчиками.
- Вложения в письмах пока не разбираются (фаза 3): AI видит, что они есть, и просит описать словами.

## 10. Файлы и фото клиентов (фаза 3)

Что умеет: замерный лист (фото или скан), спецификация или запрос КП (PDF, Excel, Word), фото двери или проёма.
Результат — в карточке сделки (блок «Файлы клиента»), примечанием в сделке и в памяти клиента (проёмы).

1. **Ключ Yandex Vision** (распознавание сканов и фото, серверы в РФ). В Yandex Cloud тому же сервисному
   аккаунту, что для SpeechKit, добавьте роль `ai.vision.user`. В `.env` достаточно `YANDEX_SPEECHKIT_API_KEY`
   и `YANDEX_FOLDER_ID`; отдельный ключ — `YANDEX_VISION_API_KEY`.
   **Без ключа** фото распознаёт запасной OCR — Tesseract прямо на сервере (бесплатно, данные никуда не уходят,
   но рукописный текст читает заметно хуже; сканы PDF без текстового слоя ему недоступны — только картинки).
   При первом файле Tesseract скачивает языковые данные rus+eng (~30 МБ) с CDN; каталог кэша —
   `TESSERACT_CACHE_PATH` в `.env`. Если серверу закрыт интернет, положите туда файлы заранее.
2. Настройки виджета → «Где работает» → «Файлы и фото клиентов»: провайдер OCR, автоматический разбор вложений
   из чатов и писем, показ фото без текста Claude, примечание в сделку, лимит файлов в сутки.
3. В карточке сделки: «Разобрать файл» → выбрать файл → результат появится под кнопкой.

Приёмка на реальных файлах заказчика (файлы не в репозитории — положите их в `evals/documents/files/`):

```bash
# без ключей — извлечение текста, чистка ПДн, маркировки; с ANTHROPIC_API_KEY — ещё и структура от модели
TEST_DATABASE_URL=postgres://... pnpm --filter @ai-door/evals eval:docs
```

## 11. Фаза 4

**Чертежи DWG.** На сервере нужен LibreDWG (`dwg2dxf`): в Docker-образе ставится автоматически (`apk add libredwg`),
на обычном сервере — `apt install libredwg-tools` (Debian/Ubuntu). Путь к бинарнику при необходимости — `DWG2DXF_BIN`.
Файлы `.dxf` разбираются без конвертера. Если конвертера нет, менеджер и AI получают понятное сообщение —
попросить у клиента PDF или картинку.

**Аналитика.** Настройки → «Аналитика»: диалоги, ответы, передачи менеджеру с причинами, конверсия (сделка ушла
вперёд по воронке после диалога с AI — любой следующий этап или успешное закрытие), расход и средняя стоимость
диалога, расход по месяцам. Этапы перепроверяются раз в 6 часов, поэтому конверсия обновляется с задержкой.

**Версии настроек.** Настройки → «Версии»: каждое сохранение — версия с автором и списком изменённых разделов;
«Показать» — поведение и модель в этой версии; «Откатить» (только админ) — возвращает настройки, текущие
сохраняются в истории.

**Удаление данных аккаунта.** Настройки → «Статус» → «Удалить все данные» (только админ, подтверждение словом
УДАЛИТЬ): удаляются настройки, переписка, память клиентов, журнал, разборы файлов, пароль почты и токены amo.
Чтобы пользоваться агентом снова — переустановить интеграцию.

**Проверки качества (раздел 14 ТЗ):**

```bash
pnpm check                                   # линтер, секреты, типы, тесты
TEST_DATABASE_URL=... pnpm --filter @ai-door/evals perf 100   # 100 одновременных диалогов (без реальной модели)
ANTHROPIC_API_KEY=... TEST_DATABASE_URL=... pnpm --filter @ai-door/evals eval   # 52 эталонных диалога на модели
```

## 13. Провайдер LLM (1.1.0)

- **Переключение**: «Модель» → «Провайдер». Без сохранённого ключа выбранного провайдера «Сохранить» недоступна
  (подсказка «Введите ключ OpenAI»). Применяется со следующего сообщения клиента во всех сделках, без перезапуска.
- **Модель**: список из API провайдера по ключу (только чат-модели с инструментами, с ценой за 1M токенов и меткой
  «видит изображения»), кэш 24 ч, «Обновить список». При первом выборе провайдера — первая рекомендованная из таблицы тарифов.
- **Резервная модель при сбое**: любая модель любого провайдера с ключом; ответ через неё помечается «fallback» в журнале.
- **Иерархия**: модель можно задать для воронки и этапа («Модель» → «Модель для воронок и этапов») и для отдельной сделки
  (панель в карточке → выпадающий список у «Провайдер · модель»). Приоритет: сделка > этап > воронка > настройки.
- **Тарифы**: «Лимиты» → «Тарифы моделей» — $ за 1M токенов по умолчанию из прайс-листов; сверить с актуальными и поправить.
  Дневной лимит ₽ считается суммарно по обоим провайдерам.
- **Сравнение и eval**: «Песочница» → «Сравнить две модели» (ответы, инструменты, токены, стоимость, время рядом) и
  «Прогнать eval на модели…» (итог по модели: пройдено, выдуманные данные, передачи менеджеру, средняя стоимость).
- **Здоровье**: если настроенная модель пропала из списка провайдера — предупреждение в «Статусе», ответы через резервную,
  задача ответственному по сделке (раз в сутки).
- Политика конфиденциальности и соглашение отдаются самим API: `https://<PUBLIC_URL>/legal/privacy`,
  `https://<PUBLIC_URL>/legal/terms`. Реквизиты издателя — `apps/api/src/legal/texts.ts`.
- Данные отключённых аккаунтов удаляются через `PURGE_UNINSTALLED_AFTER_DAYS` дней (по умолчанию 30).
