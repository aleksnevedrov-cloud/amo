## Что показали реальные файлы

- **Замерные листы** (3 фото): одностворчатая — 2,5 коробки, 5 наличников, 2,5 добора; двустворчатая — 3/6/3.
  Полотно замерщик берёт по проёму: 838 → 700, 805 → 700, 697 → 600, 1050 → 900; высота ~2050 → 2000,
  1985 → 1900 (нестандарт). Добор по стене: 95–110 → 100, 235 → 250. Эти правила зашиты в `kit.ts` и покрыты тестами.
- **Запросы клиентов** — почти все B2B: тендеры и спецификации с маркировками ГОСТ (ДВ 1 Рп 23,8х10 Г ПрБ,
  ДПС 01 EI30, ДАВ Г Оп Пр, ДСН Оп Прг…), противопожарные, стальные и алюминиевые блоки, RAL. По ТЗ это передача
  менеджеру; польза AI — структурированная разбивка позиций с пометками «не ассортимент / нестандарт» и список
  уточнений. Декодер расшифровывает типовые обозначения, непонятные токены (МдЗ, Км, Р) честно остаются
  «не расшифровано».
- Один PDF (ведомость) — чертёж с повёрнутым текстом: текстовый слой есть, но перемешан; маркировки всё равно
  находятся. Скан ТЗ на 14 страниц и баннер каталога — без текста, нужен OCR.
- В отчёте замерщика и запросе по 223-ФЗ есть адреса, ФИО, ИНН — чистка убирает их до отправки в модель
  (29 и 14 фрагментов соответственно), размеры и марки остаются.

## Что сверить по документации (п. 0.3 ТЗ) — доступа к docs с этого сервера нет

1. **Yandex Vision OCR API v1**: адреса `ocr.api.cloud.yandex.net/ocr/v1/recognizeText` и `recognizeTextAsync`,
   заголовки `Authorization: Api-Key`, `x-folder-id`, поля ответа `result.textAnnotation.{blocks,tables,fullText}`,
   формат `getRecognition` (JSON по строке на страницу), модели `page` / `handwritten`, лимиты (10 МБ, PDF в sync — 1 страница).
   Клиент написан так, чтобы правки свелись к константам.
2. **Anthropic structured outputs**: `output_config.format = {type: 'json_schema', schema}` в SDK 0.128 — используется
   без beta-заголовка; если API потребует его, добавить одну строку в `analyze.ts`.
3. **Вложения в Salesbot**: как передать ссылку на файл (`attachment_url`) в шаг виджета — тот же вопрос, что для
   голосовых (отчёт фазы 2). Без неё файлы из чата разбираются только кнопкой в карточке.

## Отклонения от ТЗ

- **Tesseract как запасной OCR** (раздел 4) не сделан: качество на рукописных замерных листах низкое, а второй
  провайдер удвоил бы код. Запасной вариант — кнопка в карточке: менеджер видит ошибку и передаёт размеры вручную.
- **`media.analyze_image` с размерами по эталону** (фото проёма с рулеткой): модель описывает тип, цвет, стиль;
  размеры по фото не оцениваются — слишком ненадёжно, вместо этого агент просит замер.
- DWG — фаза 4, как в ТЗ.

## Что понадобится при обучении

1. Ключ Anthropic и ключ Yandex Cloud с ролями `ai.speechkit.stt` и `ai.vision.user` — тогда прогоняем
   `eval:docs` на всех 12 файлах и 3 фото и правим схему/промпт по результату.
2. Уточнить у замерщика правила, которых нет в трёх листах: полотна 550/400, высота 2100+, двустворчатые
   с разными полотнами, порог.
3. Как менеджеры хотят видеть разбор B2B-запроса: примечание (сейчас) или задача с файлом расчёта.
