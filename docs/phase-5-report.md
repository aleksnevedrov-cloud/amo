# Отчёт: фаза 5 — Маркетплейс

## Критерий приёмки (раздел 15 ТЗ): виджет принят модерацией amo

⏳ Подача на модерацию требует живого аккаунта и материалов, которые делаются на нём (скриншоты, фирменные логотипы,
реквизиты юрлица). Всё, что можно подготовить в коде и документах, — готово: чек-лист раздела 16 ниже, материалы
в `docs/marketplace/`.

## Решения по ответам заказчика

| Вопрос | Ответ | Решение |
|---|---|---|
| Платно / бесплатно | Бесплатно, каждый со своим ключом | Ключ Anthropic вводится в настройках каждого аккаунта (шифруется, не показывается, проверяется без расходов). Серверный ключ остаётся запасным для РФ-Двери. Тарифы и биллинг не нужны. |
| Издатель | РФ-Двери (rf-dveri.ru) | Политика конфиденциальности и соглашение написаны от РФ-Двери и отдаются самим API (`/legal/privacy`, `/legal/terms`) — сайт трогать не обязательно. Реквизиты вписать при подаче. |

## Что сверить по документации (п. 0.3)

1. Эндпоинт `GET /v1/models` Anthropic для проверки ключа — используется как «бесплатная» проверка.
2. Требования модерации amoМаркета к областям виджета (нужна ли `digital_pipeline` при наличии `salesbot_designer`),
   к размерам логотипов и к формату скриншотов.
3. Формат подписи хука отключения (`client_uuid|account_id`, HMAC-SHA256 секретом интеграции).

## Отклонения от ТЗ

- **Ключи Yandex Cloud** (голосовые, OCR) остаются серверными: другие компании из Маркетплейса получат распознавание
  фото через Tesseract на сервере, а голосовые — только если издатель даст общий ключ. Свои ключи Yandex на аккаунт
  добавлю тем же механизмом, если публикация покажет спрос.
- **Подача на модерацию** не выполнена: нужны аккаунт, скриншоты, логотипы и реквизиты — при обучении.

## Что понадобится от заказчика для подачи

1. Фирменный логотип (сделаю нарезку под 5 размеров).
2. Реквизиты юрлица для политики и соглашения (название, ИНН, адрес) — одной строкой.
3. Доступ к аккаунту amo для скриншотов и UX-проверки (или сделать скриншоты по списку самим).
4. Сервер с доменом для `PUBLIC_URL` — чтобы ссылки на политику и redirect были постоянными.
