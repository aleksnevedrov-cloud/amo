## Дефекты и причины

| № | Дефект в PDF | Причина в коде | Исправлено |
| --- | --- | --- | --- |
| 1 | «Дверной блок (h), деревянный…» | пометка высоты из спецификации оставалась в названии | в KP-REBUILD-MAIL (`tidyName`); в черновике 50 текст старый — нужен «Собрать заново», тогда в PDF «(h)» нет |
| 2 | наименование — сплошной абзац на 12 строк: техописание + «— по прайсу» + «Комплектация» | KP-NAME складывал всё в `{{name}}`: полное название клиента, суффикс «— по прайсу: …», комплектация через перенос в том же абзаце | три уровня, каждый с новой строки (ниже) |
| 3 | служебное «по прайсу: ДВ CPL 0,2 мм» в клиентском документе | `kpLineName` добавлял источник цены в название | в документ не выводится; источник цены (`priceLabel`, `priceSource`) — только в виджете |
| 4 | «71 700 ₽ ₽» | `money()` ставит знак рубля в значение, а в шаблоне заказчика после `{{grand_total}}` стоит свой «₽» | если в шаблоне после `{{grand_total}}` / `{{price}}` / `{{sum}}` уже стоит ₽ (или «руб.»), из значения знак убирается; в журнале `kp_build` «в шаблоне знак ₽ стоит после {{grand_total}} — из значений убран». Сам шаблон `kp/28528549/template.docx` менять не нужно |
| 5 | вторая страница почти пустая: плашка «3 позиции» и примечание | явный разрыв страницы после таблицы в шаблоне плюс строки на 12 строк высотой | явные разрывы (`<w:br w:type="page"/>`, `pageBreakBefore`) после последней таблицы убираются при сборке; разрывы до таблицы и внутри неё не трогаются; в журнале «разрывов страницы после таблицы убрано: N». Строки стали в 2–3 раза ниже |

## Что сделано

| Пункт задания | Где | Содержание |
| --- | --- | --- |
| 1. priceLabel/priceSource не в КП | `packages/opt/kp/src/draft.ts` (`kpShortName`, `kpLineParts`), `kp-build.ts` | в документ идут только три уровня; «по прайсу», подпись источника и пометки менеджера остаются в виджете и журнале |
| 2. Ячейка «Наименование» в три уровня | `draft.ts`, `build.ts` (`KpTemplateData.items[].name/equipment/designation`, `withLayoutFallback`) | **Название** (в шаблоне — жирным): `priceModel` + ключевые признаки: тип («Дверной блок» / «Полотно» / «Дверь»), глухая/остеклённая, двупольная, огнестойкость, цвет из письма — «Дверной блок ДВ CPL 0,2 мм, глухой, светло-серый»; род прилагательных по типу («Полотно ДПГ сота ламинат, глухое»); если модель уже начинается с типа — не дублируется; без строки прайса — название клиента как есть. **Комплектация**: `equipment` из прайса обычным шрифтом. **Обозначение заказчика**: исходная строка из запроса (raw: с размером и количеством, без «(h)») мелким серым; выводится только когда первый уровень — короткое название по прайсу (иначе первый уровень и есть строка клиента). В шаблоне — плейсхолдеры `{{name}}`, `{{equipment}}`, `{{designation}}` отдельными абзацами; теги условий `{{#equipment}}…{{/equipment}}` — отдельными абзацами, чтобы у позиций без комплектации не оставалось пустых строк (проверено в PDF). Шаблон без этих тегов (как сейчас у заказчика): уровни идут строками под названием через перенос — «Комплектация: …», «Обозначение заказчика: …», в журнале пометка |
| 3. Итого — один знак ₽ | `build.ts` (`currencyTagsInTemplate`, `withCurrencyFallback`) | см. дефект 4; работает для любого шаблона, менять `template.docx` не требуется |
| 4. Плашка и примечание на той же странице | `build.ts` (`dropPageBreaksAfterTable`) | см. дефект 5 |
| Образец шаблона | `docs/opt/kp-template-sample.docx`, `docs/opt/kp-layout-sample.png` | таблица № / Наименование / Размер / Кол-во / Цена / Сумма (0,9 / 9,4 / 2,3 / 1,6 / 2,3 / 2,5 см); в ячейке названия: `{{name}}` жирным; `{{#equipment}}` / «Комплектация: {{equipment}}» / `{{/equipment}}`; `{{#designation}}` / «Обозначение заказчика: {{designation}}» (8,5 пт, серый) / `{{/designation}}`; итог «Итого к оплате: {{grand_total}} ({{total_qty}})» — без своего ₽. PNG — три позиции #30022107, «ДПГ + УПД, сота» и работа без прайса, одна страница |
| Виджет 1.1.8 | `KpBlock.tsx` | в плитке под полным названием клиента: «Комплектация: …», «Обозначение по прайсу: ДВ CPL 0,2 мм (ДВ 1Рп Г ПрБ)» — служебное остаётся здесь |

Попутно: цвет из письма теперь распознаётся в любом роде («серая», «белого») — иначе короткое название теряло цвет.
