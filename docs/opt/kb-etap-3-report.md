## Что сделано

| Часть | Где | Содержание |
| --- | --- | --- |
| Миграции | `packages/opt/kb/migrations/003_kb_prices_source_index.sql`, `packages/opt/kp/migrations/004_kp_research_model_key.sql` | уникальность цены на аккаунт + модель + размер + происхождение + источник (повтор обновляет); ключ модели в `kp_price_research` для кэша «один поиск на модель» |
| Ключ модели | `packages/opt/kb/src/model-key.ts` | нормализация названия позиции: без размера, количества, единиц и общих слов («дверь», «полотно», «межкомнатная»): «Дверь ДПГ сота 800×2000 мм — 12 шт» → «дпг сота»; размер и число створок из текста |
| Цены и синонимы | `packages/opt/kb/src/prices.ts` | `KbPricesRepo` (upsert, импорт прайса с заменой записей источника, список с поиском, правка, удаление, кандидаты по ключам/вхождению/триграммам), `KbAliasesRepo` (пара или строка «каноническое = синоним = синоним», `resolve`), `lookupPrice`: ключ модели с учётом синонимов → кандидаты → совпадение модели (точное › синоним › слова › похожесть) → среди них точный размер › правила нестандарта › пересчёт по площади › базовая цена; затем доверие, близость площади, свежесть. Правила нестандарта: доплаты за высоту, ширину, толщину, двупольное исполнение (%), выключатель пересчёта по площади. Срок актуальности: прайс 90 дней, страница сайта 30, веб-поиск 30 — после него цена ставится с пометкой «цена устарела». Подпись: «по базе: прайс Текона.xlsx (01.10.2026)», «по закупке (дата)», «по рынку (дата)», «изменено менеджером». Доверие по умолчанию: прайс 70, веб 40, менеджер 90, закупка 80 |
| Прайс из xlsx | `packages/opt/kb/src/price-list.ts` | шапка ищется в первых 30 строках листа, колонки — по названиям (наименование/модель/артикул, цена/стоимость, размер или ширина+высота, фабрика, ед.); без шапки — по содержимому (колонка с ценами, самая текстовая, размерная); строки без цены с единственным текстом — раздел прайса (в примечание); цены «3 450,00 ₽», «3.450», «7 900 руб.»; предпросмотр: листы, колонки с примерами, первые 20 позиций, итог и пропуски; менеджер может переназначить колонки |
| Поиск цен | `packages/opt/kp/src/research-job.ts` | 1) база: `lookupPrice` → цена в строку (`priceSource = kb`, подпись, «устарела», ссылка на запись), веб-поиск не вызывается, журнал `kp_price_research` со стоимостью 0; `force` («искать заново» / «искать в интернете») идёт мимо базы и кэша; 2) дневной лимит веб-поиска в $ (`webSearchDailyUsd`, по умолчанию 5; сумма `kp_price_research.cost_usd` за сутки) — достигнут: цена не ищется, пометка «поиск цены: дневной лимит … исчерпан» в блок, запись `kp_price_error`; 3) веб-поиск как раньше, но `maxSearchCalls` по умолчанию 5; 4) найденное — в `kb_prices` с доверием 40 под названием позиции из заявки (фабрика из карточки), ссылка на первый принятый источник |
| Кэш по модели | `packages/opt/kp/src/research-repo.ts` | `model_key`, `latestByModelKey`, `rescaleResult`: та же модель другого размера — из кэша с пересчётом статистики и принятых предложений по площади, пометка «кэш по модели, пересчёт по площади с W×H»; срок кэша по умолчанию 30 дней (было 7); `spentTodayUsd` |
| Правки менеджера | `apps/opt-api/src/routes/kp.ts` | изменённая руками цена — `priceSource = manager`, подпись «изменено менеджером», и запись в `kb_prices` (origin `manager`, доверие 90) по модели и размеру позиции |
| API | `apps/opt-api/src/routes/kb.ts` (`kbPriceRoutes`) | `GET /kb/sources/:id/prices/preview` (`?mapping=` JSON для переназначения колонок), `POST …/prices/import {mapping, factory?, validAt?, vat?, nonstandard?, confidence?}`, `GET /kb/prices?q=&sourceId=`, `POST /kb/prices` (ручная, origin manager), `PUT /kb/prices/:id`, `DELETE /kb/prices/:id`, `GET /kb/aliases`, `POST /kb/aliases {lines}` или `{alias, canonical}`, `DELETE /kb/aliases/:id`; настройки КП: `webSearchDailyUsd`, `skipKnowledgeBase`, значения по умолчанию в `GET /kp/settings` |
| Виджет | `apps/opt-widget` | плитка позиции: подпись источника цены из `priceLabel` (база / рынок / менеджер), пометка «цена устарела» (с сервера или рыночная цена старше 30 дней), строка «из базы знаний: …» и кнопка «Искать в интернете» (force) у цен из базы; вкладка «База знаний»: у xlsx-источника кнопка «Цены из прайса» → панель с выбором листа и колонок, предпросмотром, фабрикой, датой актуальности, НДС, правилами нестандарта, «Импортировать N цен»; разделы «Цены» (поиск, таблица с происхождением и доверием, ручная запись, удаление) и «Синонимы и артикулы» (строки через «=», список, удаление); настройки КП: «Не брать цены из базы знаний», «Вызовов веб-поиска на позицию», «Дневной лимит веб-поиска, $» |
| Тесты | `packages/opt/kb/test/prices.test.ts` (5), `price-list.test.ts` (4), `packages/opt/kp/test/research-repo.test.ts` (+1), `apps/opt-api/test/kb-prices.test.ts` (5), `apps/opt-widget` (+1, +дополнение) | ключ модели и правила; импорт/правка/удаление цен; подбор (точный размер › доверие, нестандарт, синоним, похожая модель, устаревшая, чужой аккаунт); колонки прайса с шапкой и без; кэш по модели с пересчётом по площади; приёмка: прайс → предпросмотр → импорт, синонимы, «Собрать КП» + «Найти цены» — 4 позиции из базы без веб-вызовов, 1 веб-поиск (Турин), второй размер Турина уже из базы (запись веб-поиска), расход < $5; «Собрать заново» + «Найти цены» — все из базы, веб-вызовов нет; «искать в интернете» (force) — веб; правка менеджера → доверие 90 и перекрывает прайс; дневной лимит останавливает поиск с пометкой |
