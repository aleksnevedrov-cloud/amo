## Причина «Command failed»

1. **imapflow прячет ответ сервера.** На любой отказ команды LOGIN (`NO` / `BAD`) imapflow бросает ошибку с текстом «Command failed» и признаком `authenticationFailed = true`. Настоящий текст сервера лежит в `responseText`, код — в `serverResponseCode`. Наш код писал в причину только `err.message`, поэтому в журнале было одно «Command failed» без объяснения.
2. **Любой отказ считался неверным паролем.** Прежний код на `authenticationFailed` ставил паузу 30 минут с текстом «вход не удался». Но вход тем же паролем прошёл за 30 секунд до этого. Значит, пароль верный. Яндекс отказывал во входе временно: частые входы подряд (сборка, пересборки, «Проверить IMAP», копия в «Отправленные») или ещё открытое соединение.
3. **Лишние входы.** Каждая пересборка входила в ящик, даже когда файл заявки уже лежал в сделке. API и воркер — разные процессы, и в каждом могли идти свои сессии к одному ящику.

Точный текст отказа Яндекса из журнала восстановить нельзя: он не записывался. После развёртывания он будет в причине, например «Command failed: [UNAVAILABLE] LOGIN Temporary error…» или «… [AUTHENTICATIONFAILED] Invalid user names or password».

Что изменено (`packages/opt/kp/src/mail-read.ts`):

| | Было | Стало |
|---|---|---|
| Причина | «Command failed» | «Command failed: [код] текст сервера» (`imapFailureText`) |
| Неверный пароль | любой отказ LOGIN | только AUTHENTICATIONFAILED / «invalid … password» / «authentication failure» и т. п.; пауза 30 мин, текст «проверьте логин и пароль приложения» |
| Временный отказ | не различался | UNAVAILABLE, «temporary», «try again», «too many», «limit», голое «Command failed» без кода. Текст: «ящик временно не пускает (…) — сервер отказал во входе, хотя пароль не отвергнут (частые входы или лишние соединения); следующая попытка не раньше ЧЧ:ММ МСК» |
| Пауза | всегда 30 мин | растёт с каждым отказом подряд: 1 → 2 → 4 → 8 → 16 → 30 мин; успешный вход сбрасывает счёт |
| Сессии | параллельные в одном процессе | одна сессия на ящик в процессе (`withMailboxSession`), следующая ждёт выхода предыдущей; ошибка одной не ломает очередь |
| Выход | `logout` в `finally` (было и раньше) | без изменений |
| Пересборка | всегда вход в ящик | вход только по «Проверить почту заново» или если в сделке нет файлов заявки (см. п. 3 ниже) |

Блокировка сессии действует в пределах процесса. API («Проверить IMAP») и воркер (сборка, отправка) — разные процессы, но теперь пересборка в ящик почти не ходит, так что входы подряд из двух процессов маловероятны.
