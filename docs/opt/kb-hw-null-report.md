# KB-HW-NULL: фурнитура без цены хранилась как 0,00

Дата: 19.10.2026. Ветка `claude/opt-kb`, коммит `7ccd1af` (после 4dd6388). Сервер (`@opt/kb`, `@opt/kp`, `apps/opt-api`) и
виджет 1.2.3. Розница и ядро не менялись (`git diff 06d538d -- packages/retail apps/api apps/worker apps/widget packages/core` = 0).

## Что было

Девять тарифов «Дополнений» без цены (OPT-009…017) записывались в `kb_prices` с `price = 0.00` — в каждом из двух прайсов,
всего 18 строк. Колонка `price` была `NOT NULL`.

| Куда протекал 0 | Последствие |
| --- | --- |
| Поиск цены в черновике | не протекал: такие строки давали исход «в прайсе цены нет», цена в черновике пустая, в КП «уточнить у менеджера». Проверено тестом на файлах заказчика |
| Медиана фурнитуры для проверки веб-цен | 0 входил в медиану. Группа «алюминиевый» (OPT-015, OPT-016 — обе без цены) давала медиану 0, и любая веб-цена отбрасывалась; группа «стекло» делилась пополам |
| Список цен в виджете и выгрузка xlsx | показывали «0 ₽» |
| Строки черновиков, где цена 0 уже записана | в документе шла строка с 0 ₽ (теоретически, если черновик искал цену до исхода «нет цены») |

## Что сделано

| Пункт | Где | Содержание |
| --- | --- | --- |
| Хранение | `packages/opt/kb/migrations/011_kb_prices_price_null.sql` | `price` допускает `NULL`; все строки прайса с ценой ≤ 0 → `NULL` (на проде — 18 тарифов); проверка `kb_prices_price_positive`: у строки прайса цена либо больше нуля, либо её нет. Веб-цены и правки менеджера не трогаются. Применяет opt-api при старте |
| Импорт | `packages/opt/kb/src/core.ts` | тариф без цены пишется как `NULL`; сверка тарифов между файлами считает «нет цены» = «нет цены» (и `NULL`, и старый 0) |
| Подбор | `packages/opt/kb/src/prices.ts` (`hasPrice`, `applyRules`, `lookupPrice`, `categoryMedian`) | у строки без цены нет цены после правил (`null`, а не 0); исход «уточнить у менеджера: цены на … (OPT-0xx) в прайсе нет», цена в ответе `null`; строка с 0 из старой базы — так же. При полностью равном совпадении строка с ценой идёт раньше строки без цены. Медиана двери, комплектующего и фурнитуры строится только по строкам с ценой |
| «Для моделей» | `lookupPrice` | подходящая двери фурнитура — в приоритете; если подходящей нет, а позиция в прайсе есть, берётся строка прайса с пометкой «уточнить у менеджера: Петля IN4000U … в прайсе для моделей INT-016, INT-018, INT-008, а дверь в заявке — INT-013», а не веб-поиск |
| Категория | `packages/opt/kp/src/research-job.ts` | позиция без ключевых слов фурнитуры («СПД40 …», «Санузловой МДФ …») по строке прайса становится фурнитурой и при исходе «нет цены» |
| Документ КП | `packages/opt/kp/src/kp-build.ts` | строка из базы с ценой 0, которая не «входит в блок», считается «нет цены»: «уточнить у менеджера», сумма «—», в итог не входит |
| Виджет 1.2.3, выгрузка | `apps/opt-widget/src/components/KbPrices.tsx`, `api.ts`, `packages/opt/kb/src/export.ts` | в списке цен и выгрузке — «нет цены» вместо «0 ₽» |
