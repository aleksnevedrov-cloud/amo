**Сверх задания, без этого наценка считалась бы неверно.** Вопрос «Нестандартный размер» предлагал «+30 % / +100 % к базе» от цены фабрики без наценки. Теперь варианты считаются так: процент к цене фабрики, затем наценка. При «Собрать заново» ответ этим вариантом (как посчитано / +30 % / +100 %) переносится выбором, а не числом. Цену заново считает поиск по текущему прайсу и наценке — иначе после смены наценки в новом черновике осталась бы старая цена. Своя цена менеджера по-прежнему переносится числом.

## Миграция

`packages/opt/kb/migrations/014_kb_markup.sql` в БД базы знаний `ai_door_opt_kb`:

```sql
ALTER TABLE kb_sources ADD COLUMN IF NOT EXISTS markup_pct numeric NOT NULL DEFAULT 0 CHECK (markup_pct >= -50 AND markup_pct <= 300);
```

- Только `ADD COLUMN`: без `UPDATE` и `DROP`. Существующие строки получают значение по умолчанию 0 средствами Postgres.
- Применяется при старте opt-api, как миграции 001–013.
- `kb_prices`, `kb_sources`, `kp_drafts`, `ai_journal` не очищаются. Строки черновиков меняет только кнопка «Пересчитать», в журнал пишутся только новые записи.
