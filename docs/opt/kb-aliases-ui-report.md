# KB-ALIASES-UI — компактный блок синонимов в «Базе знаний»

Ветка `claude/opt-kb`. Коммит кода — `b47b559`, +615 / −53 строки, 11 файлов. Виджет «Агент опт» **2.0.5**. Миграций нет. Розница не тронута (`git diff 06d538d -- packages/retail apps/api apps/worker apps/widget packages/core` — пусто).

## Что сделано

| Пункт задания | Сделано |
|---|---|
| **2.1 Свёрнут** | Блок по умолчанию свёрнут: заголовок «Синонимы (N)», кнопка «Показать / Скрыть». В свёрнутом виде виджет запрашивает только счётчики (`limit=0`), строки не грузит. |
| **2.2 Группы по прайсам** | Группы: «Оникс.xlsx — 8 154», «Межкомнатные двери.xlsx — N», …, «Добавлены вручную — N». Название группы — `kb_sources.title`, синонимы без источника — «Добавлены вручную». Каждая группа сворачивается отдельно, по умолчанию свёрнута. Строки грузятся при первом раскрытии группы. |
| **2.3 Поиск** | Поле «Найти синоним или модель» над группами. Поиск идёт на бэкенде без учёта регистра и ё/е (`translate(lower(…), 'ё', 'е') LIKE`, символы `%` и `_` экранируются) по синониму, модели (каноническое название) и ID товара. Запрос уходит через 300 мс после паузы в наборе. Группы с совпадениями раскрыты, счётчики — по совпадениям. Пустое поле снова сворачивает всё. |
| **2.4 Таблица** | Две колонки: «Синоним» и «Модель (ID)» — например, «Оникс Авангард наборный шпон (ONX-0001)». Длинный текст обрезается многоточием, полный текст — в подсказке при наведении (`title`). |
| **2.5 По 50 строк** | Внизу группы — «Ещё 50» (или «Ещё N», если осталось меньше). |
| **2.6 Высота** | Тело блока — не больше 400 px, дальше прокрутка внутри блока; страница не растягивается. |
| **2.7 Постранично** | `GET /widget/v1/kb/aliases?source_id=&q=&offset=&limit=` отдаёт `{ aliases, total, offset, limit, groups, all }`:<br>• `source_id=0` — добавленные вручную;<br>• `limit` больше 50 ограничивается 50;<br>• `groups` — счётчики по источникам с тем же поиском;<br>• `all` — всего синонимов у аккаунта (число в заголовке). |
| **3. Не сломать** | Подбор по синонимам (`resolve`, `resolveInText`) и данные `kb_aliases` не менялись. Добавление строкой «каноническое = синоним» и удаление «×» остались в новой таблице. Блоки прайсов, сайтов и наценки не тронуты. |

`POST /kb/aliases` раньше возвращал после добавления все синонимы аккаунта (8 000+). Теперь он возвращает первую страницу добавленных вручную. Виджет из ответа берёт только число добавленных, старый тест API на добавление и удаление проходит без изменений.
