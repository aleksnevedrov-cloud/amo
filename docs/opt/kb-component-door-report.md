# KB-COMPONENT-DOOR: комплектующие — только из строки прайса своей двери

Дата: 19.10.2026. Ветка `claude/opt-kb`, коммит `4458fd2` (после f5db999). Сервер (`@opt/kb`, `@opt/kp`, `apps/opt-api`) и
виджет 1.2.4. Миграций нет. Розница и ядро не менялись (`git diff 06d538d -- packages/retail apps/api apps/worker apps/widget packages/core` = 0).

## Что было (89813, черновик 64)

Коробка, наличник, добор и порог без указания двери подбирались среди всех строк комплектующих прайса по признакам, и при
равенстве бралась самая дешёвая строка. Поэтому все доборы получили 440 ₽ «Добор (ДПГ усиленная)», коробки — 1 550 ₽
«Коробка (Финская с четвертью ДПГ)», наличники — 830 ₽ «Наличник (ДПГ ПВХ)», хотя этих дверей в заявке нет. Контекст двери
(ближайшая дверь выше по заявке) работал только для многолистового прайса и только когда дверь уже нашлась.

## Как теперь

Цена коробки, наличника, добора и порога берётся только из строки прайса той двери этой же заявки, к которой они относятся.

| Шаг | Где | Содержание |
| --- | --- | --- |
| 1. Дверь — выбор менеджера | `packages/opt/kp/src/research-job.ts` (`priceComponentByDoor`) | если менеджер уже ответил на вопрос, берётся его дверь; «Найти цены» выбор не сбрасывает |
| 2. Иначе — сопоставление с дверями заявки | `packages/opt/kp/src/component-door.ts` (`matchComponentDoor`) | двери заявки группируются по строке прайса (30 строк «ДВ CPL» — одна дверь). Исключаются двери, которые явно не подходят: семейство (деревянная / стальная / алюминиевая), материал, покрытие (CPL, ПВХ…), цвет, размер двери в тексте («к двери 800×2000»). Дальше по порядку: явная ссылка «к двери …» / «для …» с моделью или названием двери; осталась одна дверь; модель / серия двери прайса названа в строке. Подошла ровно одна дверь — она |
| 3. Не определить однозначно — вопрос | `research-job.ts`, `component-door.ts` (`componentQuestionText`, `doorOptions`) | подходит несколько дверей или ни одна — цена не ставится. У строки вопрос «К какой двери считать «Коробка ТЕЛЕСКОП, сэндвич 74×2150, 35 шт»?» и список дверей заявки: ID, модель, размер, количество (при «ни одна» — все двери заявки). Менеджеру — пометка «вопрос по комплектующему: … Подходит несколько дверей заявки: INT-002 ДПГ усиленная 800×2000 мм × 5; …». Веб-поиск не вызывается |
| 4. Цена по строке двери | `packages/opt/kb/src/prices.ts` (`componentOfDoor`) | колонка этой двери: «Коробка (ДПГ усиленная)» с тем же ID товара (у одностраничного прайса — «комплектующее к <модель двери>» того же файла). Статус в карточке двери included → «входит в цену блока», в КП под дверью; not_priced или колонки нет → «уточнить у менеджера», цена пустая, не 0. Подпись в плитке «по двери INT-002, ДПГ усиленная», пометка «по двери INT-002, ДПГ усиленная (поз. 1): <почему эта дверь>» |
| 5. Дверь не из прайса | `research-job.ts` | дверь оценена по рынку или не найдена в прайсе — у её комплектующих «уточнить у менеджера: дверь «…» (поз. N) не из прайса — цены на добор к ней в прайсе нет», без цены и без веб-поиска. В заявке нет ни одной двери — так же |
| 6. Запрет чужих дверей | `prices.ts` (`lookupPrice`) | без двери строки комплектующих из колонок прайса дверей не подбираются вообще: ни «первая», ни «самая дешёвая» |
| 7. Ответ менеджера | `apps/opt-api/src/routes/kp.ts` (`POST /kp/draft/:id/component-door`), виджет | `{ requestIndex, doorRequestIndex }`: проверка, что строка — комплектующее, а выбранная — дверь этой заявки (иначе 400); выбор пишется в черновик (`componentDoor`), вопрос снимается, цена пересчитывается по строке прайса этой двери; запись в журнал |
| 8. Сборка до ответа | `packages/opt/kp/src/kp-build.ts`, виджет | «Собрать документ» недоступна, подсказка «Ответьте на вопросы по комплектующим (N)…»; сервер на сборку отвечает 409 `component_questions` «ответьте на вопросы по комплектующим: 1 (поз. 4)» |
| Виджет 1.2.4 | `apps/opt-widget/src/components/KpBlock.tsx`, `api.ts`, `styles.css` | у строки с вопросом — текст вопроса и кнопки дверей «INT-002 · ДПГ усиленная · 800 × 2000 мм · 5 шт»; после выбора — цена и подпись «по двери …», строка «дверь выбрана менеджером: поз. 1». Попутно: «Собрать документ» больше не блокируется строками «в прайсе цены нет» и «входит в цену блока» — сервер собирал их и раньше («уточнить у менеджера» / под дверью) |

Прочие комплектующие (притворная планка, капитель, карниз — без колонки в прайсе дверей) подбираются как раньше.
