## Что сделано

| Часть | Где | Содержание |
| --- | --- | --- |
| Миграция | `packages/opt/kb/migrations/002_kb_url.sql` | `kb_sources`: `crawl` (обойти раздел), `parent_id` (страница раздела → корень), `http_status`, `content_hash`; уникальность адреса на аккаунт (`kind = 'url'`) |
| Адрес | `src/safe-url.ts` | `parsePublicUrl` — при добавлении: только http/https, без логина, не localhost и не буквальный внутренний IP; `assertPublicUrl` — перед скачиванием, с разрешением имени (все адреса публичные). Своя копия правила розницы: опт не зависит от `@retail/*` |
| Скачивание | `src/fetch-url.ts` | `createUrlFetcher`: редиректы вручную (до 5), каждый адрес цепочки проверяется, лимит 50 МБ, таймаут 30 с, User-Agent `AI-Door-Agent-Opt/1.0`; ошибки текстом («HTTP 404», «таймаут 30 с», «ответ больше 50 МБ») |
| Текст страницы | `src/html.ts` | `htmlToKbText` (htmlparser2): берётся `<main>` / `[role=main]` / `<article>` / `#content`, вырезаются `nav`, `header`, `footer`, `aside`, формы, скрипты, блоки с классами меню/подвала/cookie/корзины/слайдеров; заголовки → «# …» (их подхватывает разбиение), таблицы → строки с табуляцией, списки → «- …», `alt` картинок; `sectionLinks` — ссылки раздела: тот же сайт, путь внутри раздела, без якорей и utm, пагинация (`?p=`, `?page=`, `?PAGEN_x=`) остаётся, картинки и скрипты отбрасываются, pdf/xlsx остаются |
| Ядро | `src/core.ts` | `addUrl` (повтор того же адреса — переиндексация существующего, период обновления обновляется), `index` для `url`: скачивание → страница сохраняется извлечённым текстом (`page.txt`, mime `text/html`), файл по ссылке — байтами и разбирается как файл; хэш содержимого: не изменилось → эмбеддинги не пересчитываются, только срок следующей проверки (журнал «без изменений»); заголовок источника — из `<h1>`/`<title>`; `crawl`: до 49 страниц раздела становятся источниками-детьми с тем же периодом, ставятся в очередь по одной, повтор дублей не создаёт; `refreshDue` — ссылки с подошедшим `next_refresh_at` → статус `new` и в очередь (`FOR UPDATE SKIP LOCKED`, по 20 за раз) |
| Воркер | `apps/opt-worker/src/main.ts` | очередь `kb-index` получает хук постановки страниц раздела; новая очередь `kb-maintenance` с планировщиком BullMQ `refresh-urls` раз в час → `kb.refreshDue`. Это единственная плановая задача опта; комментарий про ТЗ 6.5 уточнён |
| API | `apps/opt-api/src/routes/kb.ts` | `POST /widget/v1/kb/sources/url` `{url, refreshDays (0..365, по умолчанию 30, 0 — не обновлять), crawl}` → 202 `{source, existed}`; в представлении источника `crawl`, `parentId`, `httpStatus`; «Переиндексировать» у ссылки скачивает заново |
| Виджет | `apps/opt-widget` | форма «Ссылка»: адрес, «обновлять каждые N дн.», «обойти раздел (до 50 страниц)»; в строке источника — период и дата следующего обновления, пометки «раздел» / «страница раздела», адрес |

## Новые переменные `.env`

Нет. Период обновления по умолчанию — 30 дней (`DEFAULT_URL_REFRESH_DAYS`), обход — 50 страниц (`CRAWL_MAX_PAGES`), планировщик — раз в час; задаются в коде.

## Развёртывание

```bash
cd /opt/agent-opt/src && git pull                      # ветка с этапами 1–2
cd /opt/agent-opt
docker compose build opt-api opt-worker
docker compose up -d opt-api opt-worker                # opt-api применит 002_kb_url.sql
docker compose logs --tail=5 opt-worker                # «… kb-index и kb-maintenance (ссылки раз в час)»
docker compose exec opt-kb-db psql -U aidoor_opt_kb -d ai_door_opt_kb -c "select name from schema_migrations"   # 001_kb_init.sql, 002_kb_url.sql
```

opt-worker должен ходить в интернет по https (скачивание страниц): если сервер за прокси — задать стандартные `HTTPS_PROXY`
в `.env` опта (Node 22 их не читает сам; при необходимости добавлю поддержку отдельно). Виджет: пересобрать архив (версия 1.1.0 уже поднята на этапе 1).

## Что проверить (приёмка этапа 2)

| Шаг | Ожидание |
| --- | --- |
| «База знаний» → «Ссылка»: `https://rf-dveri.ru/ceny/` (или другая страница сайта с ценами), 30 дн. → «Добавить ссылку» | строка со статусом «в очереди…» → «проиндексирован», заголовок — название страницы, подпись «обновление каждые 30 дн., следующее <дата>» |
| «Фрагменты» у ссылки | текст страницы без меню, шапки и подвала; заголовки строками «# …»; цены из таблиц построчно |
| «Переиндексировать» | снова «проиндексирован»; в журнале «База знаний: «…» без изменений — фрагментов N» (страница не менялась) либо запись с новым числом фрагментов |
| «Ссылка» с галкой «обойти раздел», например `https://rf-dveri.ru/catalog/` | через минуту в списке — страницы раздела с пометкой «страница раздела» (не больше 49), в журнале «обход раздела … — добавлено страниц N» |
| «Проверить поиск» → вопрос по содержимому страницы | первый результат — фрагмент этой страницы с подписью «ссылка: https://…» |
| Недоступный адрес (`https://rf-dveri.ru/net-takoy/`) | статус «ошибка», текст «HTTP 404»; `http://127.0.0.1/…` отклоняется сразу |

Плановая переиндексация: `next_refresh_at` можно сдвинуть в прошлое в БД (`update kb_sources set next_refresh_at = now() where id = …`) — в течение часа источник пройдёт через очередь, в журнале появится запись `kb_index`.
