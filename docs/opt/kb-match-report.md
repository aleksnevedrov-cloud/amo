## Причина дефекта на #30022107 (черновик 40)

| Что было | Причина в коде |
| --- | --- |
| три позиции «Дверной блок деревянный внутренний глухой однопольный без порога распашной с доводчиком, …, облицовка CPL» получили 5 683 и 5 120 ₽ «по рынку», хотя в прайсе есть «ДВ CPL» 23 900 ₽ | подбор шёл по ключу названия: прошлый веб-поиск записал цены в `kb_prices` с моделью = текст письма, поэтому при повторе ключ письма совпадал с ними дословно («точное совпадение»), а строка прайса «ДВ CPL» по словам не находилась (у неё в модели два слова, у письма — пятнадцать). Точное совпадение считалось сильнее происхождения записи |

## Что сделано

| Пункт | Где | Содержание |
| --- | --- | --- |
| 1. Признаки с обеих сторон | `packages/opt/kb/src/features.ts` (новый), `price-list.ts`, `packages/opt/kp/src/draft.ts` | у позиции и у строки прайса — набор признаков: тип (блок/полотно), материал (дерево/сталь/алюминий/пластик), Г/О, створки (1/2), порог (с/без), открывание (распашная/раздвижная), покрытие (CPL/ПВХ/эмаль/шпон/экошпон/ламинат/HPL/меламин), огнестойкость (EI30/EI60/EI90/противопожарная), доводчик, замок. Из текста признаки извлекает код (`featuresOf`): слова («деревянный», «глухой», «без порога»), сокращения по ГОСТ 475-2016 («ДВ 1Рп Г ПрБ» → блок, однопольный, распашной, глухой, без порога; «ДН» — блок наружный), ДПГ/ДПО (полотно глухое/остеклённое), «EI 60», «автопорог» порогом не считается. Из прайса — из колонок «Модель», «Сокращение», «Г/О» (одна буква), «Покрытие», «Материал», «Конструкция», «Назначение», «Огнестойкость» (`featuresFromColumns`, шапка распознаётся по заголовкам, «нет» в огнестойкости = не противопожарная). Модель разбора письма дополнительно называет признаки явно (поле `features` у `request_items`, только то, что в письме сказано прямо; значения словами или кодами — `featuresFromModel`), они перекрывают извлечённые из текста. Обязательные для совпадения: тип, материал, Г/О, покрытие, огнестойкость — если известны с обеих сторон и различаются, строка отвергается; остальные повышают балл; нужно не меньше двух совпавших, из них хотя бы один обязательный. Пометка менеджеру: «по прайсу: ДВ CPL (строка 17) — совпали: дверной блок, деревянный, глухой, однопольный, без порога, распашной, CPL»; подпись на плитке — «по прайсу: ДВ CPL (строка 17)» |
| 2. Порядок источников | `prices.ts` (`lookupPrice`) | кандидаты делятся по происхождению: прайс → закупка → правка менеджера → веб; берётся первая непустая группа. Веб-запись не перебивает подходящую строку прайса, как бы «точно» ни совпал её ключ. Внутри группы: подходит по признакам › точный ключ или синоним › балл признаков › остальные виды совпадения › размер (точный › правила нестандарта › площадь) › доверие › близость площади › свежесть. При известных признаках позиции запись с расхождением по обязательному признаку отвергается в любой группе |
| 3. Веб-цены с признаками | `research-job.ts`, `prices.ts` (`upsertWith`, `backfillFeatures`), миграция `005_kb_features.sql` | результат веб-поиска пишется с признаками позиции (`features`, `feature_key`), origin `web` как и раньше. Миграция добавляет колонки и индекс; старые записи без признаков opt-api при старте заполняет из текста модели, сокращения и назначения (один раз, в логе «kb_prices: признаки заполнены у старых записей N»). Старые веб-записи «модель = текст письма» ничего не ломают: прайс выше по порядку источников, а по признакам они совпадают с той же группой |
| 4. Реалистичность веб-цены | `features.ts` (`priceListMedian`, `webPriceRealistic`, `WEB_BAND`), `research-job.ts`, `lookupPrice` | медиана цен прайса по группе признаков позиции (совместимые ключи обязательных признаков, «неизвестно» не мешает); веб-цена меньше 40 % или больше 300 % медианы — отбрасывается: позиция остаётся без цены с пометкой «поиск цены: веб-цена 5 683 ₽ отброшена: вне диапазона прайса (медиана прайса по группе 23 900 ₽, допустимо 40–300 %)», в журнале `kp_price_error` «Цена не найдена: … — веб-цена 5 683 ₽ отброшена: вне диапазона прайса (медиана по группе 23 900 ₽)» с `reason: web_price_unrealistic`, в базу такая цена не пишется. Той же проверке подвергаются веб-записи базы при подборе. Если в прайсе нет группы (алюминий) — проверки нет, веб-цена берётся |
| 5. Без ручных действий | — | синонимы по-прежнему необязательны; чистить веб-записи не нужно; «Собрать заново» → «Найти цены» даёт цену прайса |

## Развёртывание

```bash
cd /opt/agent-opt && git -C src fetch origin claude/opt-kb && git -C src checkout <коммит>
docker compose build opt-api opt-worker && docker compose up -d opt-api opt-worker   # миграцию 005 базы знаний применит opt-api при старте
docker compose logs --tail=20 opt-api | grep -i "признаки"                           # «kb_prices: признаки заполнены у старых записей N»
```

Виджет пересобирать не нужно (1.1.5). Прайс перезагружать не обязательно: признаки у существующих строк заполняются из
модели, сокращения и назначения при старте; но если в файле есть колонки «Г/О», «Покрытие», «Материал», «Конструкция»,
«Назначение», «Огнестойкость», стоит загрузить его заново — тогда признаки возьмутся из колонок, а не только из текста.
