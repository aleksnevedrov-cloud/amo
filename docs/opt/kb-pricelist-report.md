# RFD-AI-AGENT-OPT-KB-PRICELIST: прайс как единый источник цен

Дата: 16.10.2026. Ветка `claude/opt-kb`, отдельный коммит после e49076d (KP-DOWNLOAD).
Розница и ядро не менялись (`git diff -- packages/retail apps/api apps/worker apps/widget packages/core` = 0).
Виджет 1.1.4.

## Причины дефектов приёмки 16.10

| Дефект | Причина в коде |
| --- | --- |
| 1. удаление файла оставляло цены, следующий файл падал с 500 «duplicate key kb_prices_key» | `kb_prices.source_id` был `ON DELETE SET NULL`: цены удалённого прайса оставались сиротами с `source_id = NULL`; уникальный индекс `kb_prices_key` считает `coalesce(source_id, 0)`, поэтому сироты двух удалённых файлов с одной моделью и размером конфликтовали между собой при удалении второго файла |
| 2. два шага: загрузка и импорт | импорт запускался только кнопкой «Импортировать» в панели «Цены из прайса» |
| 3. два размера в ячейке → одна строка | `sizeOf()` брал первую пару чисел |
| 4. «ДВ CPL» не находится по названию из письма | подбор шёл только по ключу колонки «Наименование»; «Сокращение в названии» и «Назначение/Конструкция» не хранились |

## Что сделано

| Пункт | Где | Содержание |
| --- | --- | --- |
| а) один прайс на аккаунт | `packages/opt/kb/src/prices.ts` (`replacePriceList`), миграция `004_kb_pricelist.sql` | импорт прайса — одна транзакция: удалить все `origin = price_list` аккаунта → вставить новые; записи `manager`, `web`, `purchase` не трогаются. `kb_prices.source_id` теперь `ON DELETE CASCADE`: удаление файла удаляет его цены, сирот быть не может; `DELETE /kb/sources/:id` больше не падает |
| б) автоимпорт при загрузке | `packages/opt/kb/src/core.ts` (`importPriceList`, вызов из `index()`), `price-list.ts` (`isPriceList`, `vatFromHeader`) | после индексации xlsx-файла: если найдена шапка с колонками модели и цены и есть хотя бы одна позиция, цены импортируются сразу (НДС — по заголовку колонки цены: «с НДС» / «без НДС» / не указан); заявка без колонки цены прайсом не считается. В журнале `kb_index`: «из прайса «…» импортировано цен N автоматически, прежний прайс заменён (удалено M)». Панель «Цены из прайса» осталась для проверки и переимпорта с другой разметкой, фабрикой, датой, правилами нестандарта; ответ импорта — `{imported, skipped, replaced}` |
| в) все размеры из ячейки | `model-key.ts` (`sizesOf`), `price-list.ts` (`extractPrices`) | «Блок Ш×В: 1010×2100; 910×2100. Проход ≥800 мм — подтвердить чертежом.» → две строки цены (1010×2100 и 910×2100, одна цена); одиночные числа и пояснения не считаются; повторы убираются |
| г) дополнительные ключи и подбор по словам | `price-list.ts` (колонки `abbr`, `description`), `prices.ts` (`alt_keys`, `search_tokens`, `source_row`, `candidates`, `lookupPrice`) | колонки «Сокращение в названии» и «Назначение/Конструкция» распознаются по шапке (сокращение ищется раньше модели, чтобы «…в названии» не заняло её колонку) и хранятся у записи; их ключи — дополнительные точные ключи: название из письма, совпадающее с «Назначением», даёт точное совпадение с пометкой «найдено по прайсу: ДВ CPL (строка 17), по назначению». Нет точного совпадения — подбор по словам: доля общих слов (Жаккар) между словами позиции и словами записи (модель + сокращение + назначение) ≥ 50 % → совпадение `words`, доверие записи умножается на долю, пометка менеджеру «найдено по прайсу: ДВ CPL (строка 17), совпадение 80 %». В SQL кандидаты по словам — через GIN-индекс `search_tokens`, не меньше двух общих слов |
| д) приоритет | `prices.ts` (`ORIGIN_RANK`) | при равном совпадении модели и размера: прайс › закупка › правка менеджера › веб. Веб-цена той же модели и размера строку прайса не перебивает; правка менеджера действует там, где строки прайса на эту модель и размер нет |
| е) миграция | `004_kb_pricelist.sql` | удаляет сирот (`source_id IS NULL AND origin = 'price_list'`), меняет внешний ключ на CASCADE, добавляет колонки `abbr`, `description`, `alt_keys`, `search_tokens`, `source_row` и индексы, заполняет `search_tokens` у существующих записей из ключа модели |
| виджет 1.1.4 | `KnowledgeBase.tsx`, `KbPrices.tsx`, `api.ts` | после загрузки файла — «это прайс, импортировано цен N (прежний прайс заменён)» или «если это прайс с колонками «модель» и «цена», цены импортируются автоматически»; в карточке источника «прайс: цен N»; в панели импорта колонки «Сокращение» и «Назначение», подпись «в базе сейчас N · импорт заменит прежний прайс целиком» |

Изменение поведения, о котором стоит знать: раньше правка менеджера (доверие 90) перекрывала строку прайса (70) на ту же модель и размер; по пункту д) теперь прайс выше. Правка менеджера по-прежнему пишется в базу и применяется, когда строки прайса на эту модель и размер нет (и всегда выше веб-цены).

## Приёмка (сделка #30022107 «90025»)

1. Вкладка «База знаний» → загрузить прайс с «ДВ CPL» (размеры 1010×2100; 910×2100 в одной ячейке) → сообщение «это прайс, импортировано цен N», в карточке файла «прайс: цен N», в разделе «Цены» две строки ДВ CPL 1010×2100 и 910×2100 по 23 900 ₽.
2. В сделке «Собрать заново» → «Найти цены» → три позиции по 23 900 ₽ с подписью «по базе: прайс …», в журнале `kp_price_research` «веб-поиск не вызывался», веб-вызовов 0; в пометках позиции «найдено по прайсу: ДВ CPL (строка N), …».
3. Удалить файл прайса → его цены исчезают из раздела «Цены», ошибки нет; загрузить прайс снова → цены на месте.
