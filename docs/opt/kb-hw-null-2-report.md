# KB-HW-NULL-2: тарифы «Дополнений» попадали в двери, ID тарифа не сохранялся

Дата: 19.10.2026. Ветка `claude/opt-kb`, коммит `<COMMIT>` (после 8dbbb22). Сервер (`@opt/kb`, `apps/opt-api`); виджет не менялся
(1.2.3). Розница и ядро не менялись (`git diff 06d538d -- packages/retail apps/api apps/worker apps/widget packages/core` = 0).

## Причина

Импорт в 07:37 записал все 31 тариф правильно, с категорией «фурнитура». Категорию затёр не импорт и не миграция 011, а пересчёт
`backfillCategories` при старте opt-api. Он появился в KB-COMPONENTS для старых записей до миграции 008, но работал при каждом
старте и по всем строкам: считал категорию заново по словам названия. В названиях тарифов слов фурнитуры нет («Санузловой МДФ…»,
«Алюминиевый блок…», «Стекло СМ4…», «ECO SLIDING SET 1…»), и по умолчанию строка становилась дверью. По файлам заказчика так
уходили в двери 20 из 31 тарифа в каждом прайсе, причём и тарифы с ценой, не только девять без цены. Перезапуск при деплое
8dbbb22 это и сделал.

ID тарифа хранился в отдельной колонке `tariff_id`, а `product_id` у строк «Дополнений» оставался пустым.

## Что сделано

| Пункт | Где | Содержание |
| --- | --- | --- |
| 1. Категория «Дополнений» | `packages/opt/kb/src/core.ts` (`importPriceBook`), `prices.ts` (`upsertWith`, `backfillCategories`) | строка «Дополнений» — всегда фурнитура (работы — только по типу тарифа «работы / услуга / монтаж / доставка»; в файлах заказчика у всех 31 тип `option`). У строки, категорию которой задал импорт, ставится признак `category_fixed`; пересчёт при старте трогает только строки без него (веб-цены и правки до KB-COMPONENTS). Повторная запись той же строки без категории её категорию не меняет |
| 2. ID тарифа | `core.ts`, `prices.ts` (`rowsByProductId`, `lookupPrice`) | `product_id` = ID тарифа (OPT-0xx), `tariff_id` — тот же. Синоним тарифа внутри названия позиции («СПД40 … для алюминиевой двери» → OPT-012) переводит позицию из «двери по умолчанию» в фурнитуру и находит строку тарифа |
| 3. Записанные строки | `packages/opt/kb/migrations/012_kb_prices_category_fixed.sql` | колонка `category_fixed`; у строк прайса с ID тарифа — категория «фурнитура» и `product_id = tariff_id`; комплектующие листа 1 («Наличник (ДПГ CPL)», описание «комплектующее к …») — «комплектующее» с видом; двери листа 1 (ID товара есть, тарифа нет) — «дверь»; все строки прайса — `category_fixed = true`. Применяет opt-api при старте; перезаливать прайсы не нужно |

Виджет не меняется (1.2.3). В логе после старта строки «kb_prices: категории уточнены у старых записей» по прайсам быть не должно.

Приёмка (только чтение):

```sql
SELECT source_id, category, count(*), count(product_id) FROM kb_prices
 WHERE source_id IN (32, 33) AND product_id LIKE 'OPT%' GROUP BY source_id, category ORDER BY source_id;
-- ожидание: 32 | hardware | 31 | 31  и  33 | hardware | 31 | 31
SELECT source_id, count(*) FROM kb_prices WHERE source_id IN (32, 33) AND category = 'door' GROUP BY source_id ORDER BY source_id;
-- ожидание: 32 | 30  и  33 | 20
SELECT count(*) FROM kb_prices WHERE source_id IN (32, 33) AND tariff_id IS NOT NULL AND (category <> 'hardware' OR product_id IS DISTINCT FROM tariff_id);
-- ожидание: 0
```

Если у аккаунта остался одностраничный «Прайс_фурнитура…xlsx», его строки без слов фурнитуры в названии могли раньше тоже уйти в
двери тем же пересчётом. Миграция их категорию не угадывает: такой файл достаточно загрузить заново, дальше категория из импорта фиксируется.
