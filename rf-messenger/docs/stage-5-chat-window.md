# Окно переписки в карточке сделки (как у Wazzup)

Ветка `claude/new-session-vpbkn3`, папка `rf-messenger/`. Сервер: `server/src/api/chat.ts` (API окна), `server/src/bridge.ts`
(отправка из окна, история, статусы, события), `server/migrations/004_chat_window.sql`. Виджет: `widget/src/chat.ts` (окно),
`widget/src/templates.ts` (переменные, поиск), `widget/src/templates-ui.ts` (управление шаблонами).

## Что сделано (по пунктам ТЗ)

| № | Реализация |
|---|---|
| 1 | Окно `position: fixed` поверх правой колонки карточки: ищется по селекторам `.card-holder__right`, `.card-holder .notes-wrapper`, `.card-fields__right`, … (`RIGHT_COLUMN_SELECTORS`), повторяет её размер и следит за ним (ResizeObserver, resize, scroll). Если колонка не найдена — правые 58 % экрана. Левая колонка остаётся рабочей. Открытие — кнопкой «Открыть переписку» в блоке «Rf Messenger» правой панели. Значок у контакта: amoCRM не даёт встроиться в поля контакта без правки чужой разметки, поэтому вторая точка входа — кнопка «Написать» в том же блоке (открывает экран выбора канала и номера) |
| 2 | Зелёная вкладка с × на правом краю и Esc (Esc сначала закрывает всплывающие панели, затем окно) |
| 3 | Шапка: ☰ (все чаты контакта по каналам, непрочитанные, последнее сообщение), имя клиента, значок канала + номер или ник; справа — поиск, «Сделки» (сделки контакта, переход в новой вкладке), ⋮ (загрузить историю, мои шаблоны, открыть в чате amoCRM, скопировать номер) |
| 4 | Одна лента: клиент слева, менеджер справа с именем (из окна — имя сотрудника amoCRM, из amo — имя отправителя из вебхука, Salesbot — «amoCRM»); дата-разделители «Сегодня / Вчера / 5 ноября»; время; статусы 🕓 / ✓ / ✓✓ / ✓✓ синие / ! с кнопкой «Повторить» и текстом ошибки; фото — превью и просмотр на весь экран; видео — плеер; голосовые и аудио — плеер; файлы — скачивание; цитаты с переходом к сообщению; имя автора в группах. События робота и системные записи amoCRM в окно не попадают — в БД только сообщения. Прокрутка вверх подгружает по 50 (`before=<id>`, порядок по времени) |
| 5 | 📎 (выбор файлов, перетаскивание в окно, вставка ⌘V), «/» — шаблоны, 😊 — эмодзи, поле «Введите сообщение…» (Enter — отправить, Shift+Enter — перенос, авто-высота), 🎤 — запись (MediaRecorder; ogg/opus где поддерживается, иначе webm/opus). Ответ на сообщение — кнопка ↩ при наведении на пузырь |
| 6 | Открывается последний активный чат (по времени последнего сообщения), переключение через ☰. Нет чатов — экран «Написать» (канал + номер из контакта; VK и MAX — выбор из тех, кто уже писал) |
| 7 | «/» в начале поля или кнопка «/» — список с поиском по названию, папке и тексту; ↑↓ выбор, Enter вставляет (текст можно править), Enter — отправить. Вложения шаблона добавляются к сообщению |
| 8 | Шаблон: название, текст, папка, вложения (фото, PDF — через загрузку файлов) |
| 9 | Переменные `{имя_клиента}`, `{имя_менеджера}`, `{номер_сделки}`, `{бюджет}`, `{поле:Название поля}` (любое поле сделки, регистр не важен). Подставляются при вставке из контекста карточки (`GET /chat/v1/templates/context`); пустые остаются в тексте и подсвечиваются жёлтой полосой над полем, пока их не поправят |
| 10 | Общие — администратор (настройки виджета → «Общие шаблоны»), личные — каждый менеджер (⋮ → «Мои шаблоны»). Сортировка по частоте использования (`use_count`), затем папка и название |
| 11 | Таблица `templates` с `account_id`; `owner_user_id` NULL — общий. Правка и удаление общих — только администратор (иначе 404), личных — только владелец |
| 12 | Живые события: SSE `GET /chat/v1/events` по сеансу окна. Процесс connectors публикует в Redis (`rfm:chat:events:<account>`): новое сообщение, смена статуса (отправлено / доставлено / прочитано / ошибка), загружена история. Открытый чат помечается прочитанным при открытии и при новом входящем |
| 13 | История: при первом сообщении нового чата ставится задача `history`, и по ⋮ → «Загрузить историю». Telegram личный — `messages.getHistory` (до 100, старше самого старого известного); WhatsApp — `fetchMessageHistory` относительно самого старого известного сообщения (Baileys отдаёт историю только по запросу от известной точки; сработает, когда телефон в сети). Сохраняется с `from_history = true` и временем из мессенджера; в amoCRM не передаётся (исключено из очереди и из повтора зависших) |
| 14 | Отправка из окна — `bridge.sendFromWindow`: клиенту через коннектор, затем в amoCRM тем же путём, что сообщения с телефона: исходящее от сотрудника (`sender.ref_id` — amojo_id нажавшего), `silent`. В ленте сделки появляется как исходящее этого менеджера |
| 15 | Администратор — все чаты аккаунта. Менеджер — чаты сделок, где он ответственный, и контактов, где он ответственный (проверка через REST amoCRM при открытии карточки); доступ к чату запоминается на час (ACL в Redis). Чужая сделка — 403, чужой чат — 404 |
| 16 | Все JSON-маршруты `/chat/v1/*` — с `X-Auth-Token` amoCRM, `account_id` из токена, rate limit на каждом, тело до 1 МБ. SSE и загрузка файлов — по сеансу (`POST /chat/v1/session` выдаёт случайный токен на 1 час по токену amo: EventSource не умеет заголовки, а `$authorizedAjax` — FormData). Файлы — multipart до `MAX_FILE_MB` |
| 17 | Классы `rfm-cw-*`, светлая тема, шрифты amoCRM; минимальная ширина окна 360 px, рассчитано от 1280 px |

Миграция `004_chat_window.sql`: `chats.read_at`, `messages.sender_name / sender_user_id / from_history`, индекс по времени, таблица `templates`.

## API окна

| Маршрут | Назначение |
|---|---|
| `POST /chat/v1/session` | Сеанс для SSE и файлов |
| `GET /chat/v1/chats?leadId= \| contactId=` | Чаты карточки (контакты сделки → привязанные чаты amo + чаты по телефонам), непрочитанные, каналы для «Написать» |
| `GET /chat/v1/chats/:id/messages?before=&limit=` | Страница сообщений (50) |
| `GET /chat/v1/chats/:id/search?q=` | Поиск по переписке |
| `POST /chat/v1/chats/:id/messages` | Отправка: `{text, replyToMessageId, fileIds}` |
| `POST /chat/v1/chats/:id/read` | Прочитано |
| `POST /chat/v1/chats/:id/history` | Загрузить историю |
| `POST /chat/v1/messages/:id/retry` | Повтор недоставленного из amo |
| `GET /chat/v1/contacts/:id/leads` | Сделки контакта |
| `GET/POST/PUT/DELETE /chat/v1/templates`, `POST …/:id/used`, `GET …/context` | Шаблоны и контекст переменных |
| `POST /chat/v1/files` (multipart, `X-Rfm-Session`) | Загрузка файла |
| `GET /chat/v1/events?session=&chats=` | SSE |

## Проверка

| Команда | Результат |
|---|---|
| `pnpm lint`, `pnpm typecheck` | без замечаний |
| `pnpm test` | server: 149 тестов (13 новых: чаты и права, ACL, пагинация, поиск, отправка с именем менеджера и ref_id, файл по сеансу, прочитанность и статусы, повтор, история, SSE, шаблоны и права, контекст переменных); widget: 21 (8 новых: переменные, поиск и «/», лента и статусы, список чатов, окно поверх колонки, шаблон по «/» и отправка с цитатой, экран «Написать», положение окна) |
| `pnpm build` | `server/dist`, `widget/dist/widget.zip` |

Новая зависимость сервера: **`@fastify/multipart`** (загрузка файлов из окна).

Ограничения, о которых стоит знать:
- Запись голосовых: Chrome пишет webm/opus (ogg/opus не умеет). WhatsApp показывает такое сообщение как аудиофайл, а не как «голосовое с волной»; Telegram — как аудио. Перекодирование в ogg на сервере потребовало бы ffmpeg в образе — отдельной задачей, если нужно.
- История WhatsApp зависит от телефона: Baileys запрашивает её у телефона, ответ приходит, когда телефон в сети. Telegram личный отдаёт историю сразу. Telegram-бот, MAX, VK и Авито историю не отдают — кнопки нет.
- Разметка карточки amoCRM меняется; если окно встанет не над лентой, селекторы правятся в `RIGHT_COLUMN_SELECTORS` (один массив).

## Выкладка (чат с доступом к серверу)

| № | Шаг |
|---|---|
| 1 | `cd /opt/rf-messenger/src/rf-messenger && git pull`, затем `sh /opt/rf-messenger/deploy.sh </dev/null` — миграция `004` применится при старте |
| 2 | Новых переменных `.env` нет. Для SSE в nginx внутри `location /` добавить: `proxy_buffering off; proxy_read_timeout 3600s; proxy_http_version 1.1; proxy_set_header Connection '';` — иначе события копятся в буфере nginx и соединение рвётся через 60 с |
| 3 | `client_max_body_size` в nginx — не меньше `MAX_FILE_MB` (сейчас 2m: поднять до `50m`, иначе фото из окна не загрузятся) |
| 4 | Проверка: `curl -sS -o /dev/null -w '%{http_code}' https://chat.rf-dveri.ru/chat/v1/events?session=x` → `401`; `POST /chat/v1/session` без токена → `401` |
| 5 | Заказчик загружает новый `widget.zip` в интеграцию («Редактировать» → «Загрузить» → «Сохранить»), обновляет карточку сделки |
| 6 | Приёмка на тестовом чате: открыть карточку → «Открыть переписку» → окно над лентой; текст, фото, голосовое; «/» со вставкой шаблона; ☰; ⋮ → «Загрузить историю» (Telegram личный); новое входящее появляется без перезагрузки; в ленте сделки отправленное видно как исходящее менеджера |

Новая зависимость: `@fastify/multipart` — отдельной строкой.
