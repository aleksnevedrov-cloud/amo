# Этап 4 — каналы MAX, VK и Авито

Ветка `claude/new-session-vpbkn3`, папка `rf-messenger/`. Один канал — один файл: `server/src/connectors/{max,vk,avito}.ts`,
общий HTTP-слой с повторами — `server/src/connectors/http.ts`.

## Что сделано

| Пункт задачи | Реализация |
|---|---|
| 1. MAX (бот) | Ввод в виджете: токен бота. Приём — long polling `GET /updates` (внешний адрес не нужен), маркер двигается после обработки пачки. Текст, фото, файлы, голосовые, видео, стикеры в обе стороны; группы (имя автора в тексте), ответ с цитатой (`link.reply`), «печатает…». Файлы — `POST /uploads` + загрузка; `attachment.not.ready` повторяется |
| 2. VK (сообщество) | Ввод: id сообщества и ключ доступа. Приём — Bots Long Poll API (`groups.getLongPollServer`, при `failed` — новый сервер); при подключении сервис сам включает Long Poll с событием «Входящее сообщение» (`groups.setLongPollSettings`), если у ключа есть право управления. Текст, фото (`photos.getMessagesUploadServer` → `saveMessagesPhoto`), документы и голосовые (`docs.getMessagesUploadServer` → `docs.save`), ответ с цитатой (`reply_to`), «печатает…». `messages.send` с `random_id`, одинаковым во всех повторах одного запроса — дубля у клиента не будет. Видео VK — ссылкой на страницу |
| 3. Авито (Messenger API) | Ввод: client_id, client_secret, id профиля; id сверяется с `GET /core/v1/accounts/self`. Токен `client_credentials` кэшируется и обновляется за минуту до истечения; на 401 — обновление и один повтор. Входящие — вебхук v3 на `https://chat.rf-dveri.ru/hooks/avito/<id канала>/<секрет>` (секрет 48 hex, хранится зашифрованным в ключах канала); если подписка не удалась — опрос непрочитанных чатов раз в минуту, если удалась — раз в 5 минут как подстраховка. Прочитанными в Авито помечаются только чаты, переданные в amoCRM. Текст и фото в обе стороны; голосовые от клиента — тоже (через `getVoiceFiles`). Название объявления и ссылка — в первом сообщении чата: «Объявление: «…»\nhttps://www.avito.ru/…». Сообщения, отправленные из приложения Авито, попадают в amoCRM как исходящие |
| 4. Статусы | «Подключён»; «Ошибка» с текстом: неверный токен/ключ, нет прав (VK — какие именно права нужны и что включить в сообществе), нет доступа к Messenger API (Авито), нет связи — повторное подключение. Авито без вебхука — «Подключён» с пометкой про опрос |
| 4. Виджет | Плитки «Telegram-бот», «MAX», «VK», «Авито» с отдельными формами вместо «Скоро»; ключи — поля `password`, после отправки стираются, в ответах API не возвращаются; в БД — AES-256-GCM |
| 4. Повторы | Общий `HttpClient`: сетевая ошибка, таймаут, 429 и 5xx — до 5 повторов с паузой 1–2–4–8–16 с (±25 %), для 429 — `Retry-After`; у VK также коды 1, 6, 9, 10. Успешный ответ не повторяется. Переподключение опроса — 30 с → 10 мин |
| 4. Вложения | Скачивание — 90 с, лимит `MAX_FILE_MB`, проверка адреса на внутреннюю сеть (`assertPublicUrl`) и редиректов; общий таймаут 90 с в мосте |
| 4. Уведомления | Каналы MAX, VK и Авито добавлены в общий механизм: не «Подключён» дольше 5 мин → сообщение в Telegram, при восстановлении — второе |
| 4. Маршруты API | Новый: `POST /hooks/avito/:channelId/:secret` — секрет сравнивается за постоянное время с ключами канала, 404 для чужого канала и неверного формата, 401 для неверного секрета, rate limit 600/мин, тело до 1 МБ (общий лимит), тело уходит в очередь BullMQ `rfm-webhooks` процессу connectors (5 попыток). Поля `/widget/v1/compose` и `/widget/v1/chats/start` расширены (см. ниже), авторизация прежняя |
| 4. «Написать» из карточки | VK и MAX — только тем, кто уже писал сообществу или боту: в окне «Написать» вместо номера — список чатов канала (последние 50 личных чатов аккаунта), в API — `chatId` вместо `phone`; мост проверяет, что чат принадлежит аккаунту и каналу. Авито — не предлагается, запрос с `chatId` в канал Авито отклоняется |
| Прокси | MAX, VK и Авито — российские сервисы, идут **напрямую**, минуя прокси Telegram/WhatsApp |

## Проверка

| Команда | Результат |
|---|---|
| `pnpm lint`, `pnpm typecheck` | без замечаний |
| `pnpm test` | server: 136 тестов, widget: 13 — все зелёные |
| `pnpm build` | `server/dist/{api,connectors,migrate}.js`, `widget/dist/widget.zip` (script.js 36 КБ) |

Новые тесты: `max.test.ts` (8), `vk.test.ts` (8), `avito.test.ts` (8), `stage4-api.test.ts` (4), 4 теста виджета:
разбор входящих (текст, фото, файл, голосовое, цитата, группа, объявление Авито, служебные события), отправка
(текст с цитатой, фото через серверы загрузки, `random_id`, не-фото в Авито), повторы (5xx, 429, коды VK 6/10,
`attachment.not.ready`), ошибки авторизации (401 MAX, код 5 VK, `invalid_client` Авито — статус «Ошибка» и остановка),
long polling MAX и VK (маркер/ts, `failed=2`), вебхук Авито (подписка, разбор, секрет, чужой канал), подключение из
виджета (проверка ключей у сервиса, шифрование, ключи не возвращаются), «Написать» в существующий чат.

С настоящими API MAX, VK и Авито код не проверялся — только с заглушками по документации. Расхождения
(имена полей, формат ответов загрузки) проявятся на приёмке и правятся точечно.

Миграций БД нет: ключи каналов лежат в существующем поле `channels.credentials`, новых переменных `.env` нет.

## Выкладка (чат с доступом к серверу)

| № | Шаг |
|---|---|
| 1 | `cd /opt/rf-messenger/src/rf-messenger && git pull` (коммит этапа 4), затем `sh /opt/rf-messenger/deploy.sh </dev/null` — пересборка api, connectors и архива виджета |
| 2 | Новых переменных в `.env` нет. Проверить, что `PUBLIC_URL=https://chat.rf-dveri.ru`: от него строится адрес вебхука Авито |
| 3 | nginx: путь `/hooks/` должен доходить до сервиса (при `location /` — уже доходит). Проверка снаружи: `curl -s -o /dev/null -w '%{http_code}' -X POST https://chat.rf-dveri.ru/hooks/avito/1/abc` → `404` (не 502 и не 301) |
| 4 | Заказчик загружает новый `widget.zip` в интеграцию «РФ-Мессенджер» (версия в манифесте `0.2.<число>` растёт) |
| 5 | В журнале connectors после запуска: `коннектор запущен` для каждого канала; ключи и токены в журнал не пишутся |

Память: три коннектора — это HTTP-опросы, без браузера и сессий; прирост RSS процесса connectors ≈ 5–15 МБ на все каналы.

## Приёмка (по ТЗ, этап 4: текст и фото в обе стороны по каждому каналу)

| Канал | Что нужно от заказчика | Проверка |
|---|---|---|
| MAX | Токен бота от @MasterBot | Плитка «MAX» → токен → статус «Подключён». Сообщение боту с телефона → сделка в amoCRM; ответ из amoCRM → в MAX; фото в обе стороны |
| VK | id сообщества; ключ доступа (Управление → Работа с API → Ключи доступа: сообщения, фотографии, документы, управление сообществом); в сообществе включены сообщения | Плитка «VK» → id и ключ → «Подключён». Сообщение сообществу → сделка; ответ → в VK; фото в обе стороны; «Написать» из карточки — клиенту, который уже писал |
| Авито | client_id, client_secret приложения с доступом к Messenger API; id профиля | Плитка «Авито» → ключи → «Подключён» (без пометки про опрос — значит вебхук подписался). Сообщение по объявлению → сделка с названием и ссылкой на объявление; ответ → в Авито; фото в обе стороны |

Тестировать только на тестовых чатах; клиентам не писать.

## Откат

`git checkout <предыдущий коммит>` в рабочей копии и `sh /opt/rf-messenger/deploy.sh </dev/null`. Каналы MAX/VK/Авито,
созданные до отката, останутся в БД со статусом «Этот тип канала будет доступен на следующем этапе» — удалить их в виджете.
Миграций нет, данные других каналов не затронуты.
