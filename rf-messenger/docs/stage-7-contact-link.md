# Привязка нового чата к существующему контакту по номеру (без дублей в неразобранном)

Ветка `claude/new-session-vpbkn3`, папка `rf-messenger/`. Файлы: `server/src/amo/contact-match.ts` (подбор контакта,
чистые функции), `server/src/amo/rest.ts` (`contactsByPhone`, ограничитель 7 запросов/с), `server/src/bridge.ts`
(`linkNewChatToContact`, очередь по чату), тесты `server/test/contact-link.test.ts`.

## Диагностика (п. 2) — по коду; подтвердить на сервере запросами ниже

| № | Ответ |
|---|---|
| 2.1 | По коду: оба исходящих ушли **с телефона менеджера**, не кнопкой «Написать». В `startChat` («Написать») чат привязывается к контакту сделки до первого сообщения, и amoCRM не заводит дубль — а здесь дубли появились. Сообщение с телефона приходит в `onInbound` с `fromMe`, сохраняется как `source = 'phone'` и уходит в amo через `deliverToAmo` без какой-либо привязки. Подтверждение в БД: `SELECT m.source, m.direction, m.created_at FROM messages m JOIN chats c ON c.id = m.chat_id WHERE c.amojo_chat_id IN ('b82e07c7-929f-4f48-89f5-2142803d90a8','c5be915c-6f16-456e-9d4e-603efc5c2717') ORDER BY m.created_at;` — у первых сообщений ожидается `source = phone`, `direction = out` |
| 2.2 | Не применимо, если 2.1 подтвердится. Если же в БД первое сообщение окажется от «Написать» (у него тоже `source = phone`, но у чата `amojo_chat_id` появляется до первого сообщения, а в журнале connectors есть строка `написать первым`), значит `rest.linkChat` вернул ошибку — она есть в журнале api/connectors за 13:31 и 16:49 МСК 12.11 со словами `linkChat` или `уже привязан к другому контакту` |
| 2.3 | Вид канала хранится в БД: `SELECT id, kind, title FROM channels WHERE id = 8;`. Судя по тому, что номера собеседников известны и сообщения с телефона доходят, это WhatsApp (Baileys) или MAX по номеру (GREEN-API); Telegram личный тоже возможен, если номер виден. Точный ответ — из запроса |

## Что сделано (п. 3)

| № | Реализация |
|---|---|
| 3.1 | В `deliverToAmo` перед `amojo.sendMessage` вызывается `linkNewChatToContact`: для чата без `amojoChatId` (не группа, номер известен) — поиск контакта → `amojo.createChat` → `rest.linkChat` → затем сообщение. Срабатывает и на первом входящем, и на первом сообщении с телефона |
| 3.2 | `AmoRest.contactsByPhone`: `GET /api/v4/contacts?query=<последние 10 цифр>&with=leads&limit=50`, затем точное сравнение последних 10 цифр с каждым значением поля PHONE; сделки найденных контактов — одним `GET /api/v4/leads?filter[id][]=…` (статус, updated_at) |
| 3.3 | Один контакт → привязка к нему |
| 3.4 | Несколько → `chooseContact`: контакт с самой свежей открытой сделкой (статус не 142/143), иначе контакт с самым свежим `updated_at`. Причина выбора пишется в журнал (`reason`) |
| 3.5 | Не найден → как раньше: без `createChat`, телефон в `profile.phone` клиента |
| 3.6 | Номер неизвестен (MAX с телефона, Telegram без номера) → поиска нет |
| 3.7 | Группы → поиска и привязки нет |
| 3.8 | `startChat` не менялся: привязка к контакту сделки; у такого чата уже есть `amojoChatId`, поэтому поиск по номеру для него не запускается |
| 3.9 | Есть `amojoChatId` → поиска нет |
| 3.10 | Сбой или таймаут поиска (5 с, `contactLookupTimeoutMs`) и ошибка `createChat`/`linkChat` → сообщение уходит как раньше, в журнал предупреждение (номер — последние 4 цифры) |
| 3.11 | Передача в amo по одному чату строго по очереди (`perChat`): задачи очереди для одного чата выполняются последовательно, быстрый ответ клиента не обгонит привязку, начатую на исходящем |
| 3.12 | `RateLimiter(7)` на все запросы REST amoCRM процесса; результат поиска по номеру кэшируется 10 минут (аккаунт + 10 цифр → id контакта или «нет») |
| 3.13 | Документацию amoCRM с этой среды открыть не удалось (сеть закрыта для amocrm.ru). По документации API чатов, которую я помню, и по поведению «Написать» в этом же проекте: чат, созданный `POST /v2/origin/custom/{scope_id}/chats` и привязанный через `POST /api/v4/contacts/chats` до первого сообщения, при входящем попадает к этому контакту — в его открытую сделку или новой сделкой у него; неразобранное создаётся только для чата без контакта. Именно так работает «Написать» сейчас, дублей там не было. Подтверждается приёмкой (п. 6.5): если дубль всё же появится, запасной способ — создавать сделку у контакта самим через `POST /api/v4/leads` с привязкой контакта перед первым сообщением |

Новых зависимостей и миграций нет.
