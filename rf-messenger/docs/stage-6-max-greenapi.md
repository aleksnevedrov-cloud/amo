# MAX по номеру телефона через GREEN-API (вид канала `max_phone`)

Ветка `claude/new-session-vpbkn3`, папка `rf-messenger/`. Коннектор — `server/src/connectors/max-greenapi.ts` (по образцу
`whatsapp.ts`), миграция `005_max_phone.sql` (новый вид канала в ограничении `channels.kind`). Существующий канал
«MAX» (бот) не менялся. Документация, по которой написан клиент: https://green-api.com/v3/docs/ (API MAX, v3).

## Что сделано

| № | Реализация |
|---|---|
| 1 | Плитка «MAX по номеру»: idInstance (открыто) и apiTokenInstance (поле-пароль). При сохранении ключи проверяются `getStateInstance`, хранятся зашифрованными (AES-256-GCM), в ответах API и статусе не возвращаются. Если инстанс не авторизован — виджет показывает QR (метод `qr`, PNG base64, обновляется каждые 5 с, опрос как у WhatsApp) с подсказкой «MAX → Настройки → Устройства → Подключить устройство; пароль для входа в MAX должен быть отключён». После входа — номер из `getAccountSettings.phone`, название «MAX +7…», статус «Подключён» |
| 2 | Приём: при подключении сервис сверяет `getSettings` и, если нужно, выставляет `setSettings`: `webhookUrl = https://chat.rf-dveri.ru/hooks/greenapi/<id канала>`, `webhookUrlToken = Bearer <секрет>`, `incomingWebhook`, `outgoingMessageWebhook`, `outgoingWebhook`, `stateWebhook` = yes, `outgoingAPIMessageWebhook` = no (без нужды инстанс не перезапускается). Маршрут проверяет заголовок `Authorization` за постоянное время. Если `PUBLIC_URL` нет или настройки не применились — опрос `receiveNotification` / `deleteNotification`. Обрабатываются `incomingMessageReceived` (клиент), `outgoingMessageReceived` (с телефона → в amoCRM как исходящее), `outgoingAPIMessageReceived` (наши отправки, пропуск — без дублей), `outgoingMessageStatus` (delivered / read → статусы, failed / noAccount / notInGroup → «не доставлено» в окне и amo), `stateInstanceChanged` |
| 3 | Текст, фото, видео, документы, голосовые (audioMessage: ogg/opus → голосовое, иначе аудио), стикеры, геопозиция, контакт; цитаты в обе стороны (`quotedMessage.stanzaId` ↔ `quotedMessageId`); группы — название (`chatName`) и автор (`senderName`). Вложения входящих — по `downloadUrl` с таймаутом 90 с и лимитом `MAX_FILE_MB` (общий `HttpClient.download`); исходящие файлы — `sendFileByUpload` на media-хост, текст — подписью; длинный текст — частями по 4000 |
| 4 | «Написать» из карточки: номер из контакта → `checkAccount` (только РФ 7… и РБ 375…, как требует GREEN-API) → `chatId`; нет MAX — «Номер … не найден в мессенджере»; лимит проверок GREEN-API — понятная ошибка |
| 5 | Статусы канала: `authorized` → «Подключён»; `notAuthorized` → «Нужен вход по QR…»; `blocked` → «Заблокирован»; `suspended` → «Ограничен (suspended): отправка только на номера из контактов до … МСК»; `pendingPassword` → подсказка отключить пароль; `starting` → «Подключается»; 401/403 на ключи → «GREEN-API не принял idInstance или apiTokenInstance». Повторы при сети, 429 и 5xx — общий `HttpClient`; уведомления о сбоях — общий механизм (`max_phone` в наблюдаемых); без прокси |
| 6 | Пауза 1–3 с между исходящими в один чат — общий механизм очереди (RedisPacer); **новое:** не больше 20 первых сообщений новым номерам в сутки на канал (`NEW_CHATS_PER_DAY`, считается по чатам без входящих за сутки) — действует для всех каналов с «Написать»; рассылок нет: отправка только ответом или одним первым сообщением из карточки |
| 7 | `POST /hooks/greenapi/:channelId`: rate limit 1200/мин, тело до 1 МБ (общий лимит), 404 для чужого вида канала и некорректного id, 401 при неверном токене, тело — в очередь `rfm-webhooks` процессу connectors. API виджета — токен amoCRM, `account_id` из токена |
| 8 | Тесты `max-greenapi.test.ts` (14): нормализация всех типов уведомлений (текст, ссылка, цитата, фото, видео, документ, голосовое, аудио, стикер, геопозиция, контакт, группа, с телефона, через API — пропуск, реакции и каналы — пропуск, статусы, состояние), хосты и настройки инстанса, токен вебхука, отправка (токен не в тексте ошибок), QR-цикл и вход, опрос без вебхука, неверные ключи / blocked, статусы доставки и ошибки доставки через вебхук, checkAccount, подключение из виджета, маршрут вебхука (Bearer, чужой канал, QR-картинка), лимит 20 первых сообщений. Виджет: 2 теста (плитка, форма, QR с подсказкой; карточка канала) |

Хосты API выводятся из idInstance (`1101…` → `https://1101.api.green-api.com`, медиа — `https://1101.media.green-api.com`);
если в кабинете другие — их можно положить в ключи канала (`apiUrl`, `mediaUrl`).

## Выкладка (чат с доступом к серверу)

| № | Шаг |
|---|---|
| 1 | `cd /opt/rf-messenger/src/rf-messenger && git pull && sh /opt/rf-messenger/deploy.sh </dev/null` — миграция `005` применится при старте |
| 2 | Новых переменных `.env` нет. Вебхук строится из `PUBLIC_URL`; путь `/hooks/` должен доходить до сервиса (при `location /` — доходит) |
| 3 | Проверка снаружи: `curl -s -o /dev/null -w '%{http_code}' -X POST https://chat.rf-dveri.ru/hooks/greenapi/1` → `404`; с заголовком `-H 'Authorization: Bearer x'` на существующий канал → `401` |
| 4 | Заказчик загружает новый `widget.zip` |
| 5 | Приёмка **только на тестовом номере**: в console.green-api.com создать инстанс MAX, в виджете плитка «MAX по номеру» → idInstance и apiTokenInstance → QR → сканировать в MAX (Настройки → Устройства → Подключить устройство, пароль входа отключён) → статус «Подключён» с номером. Текст и фото в обе стороны, голосовое, цитата, сообщение с телефона видно в amoCRM исходящим, «Написать» из карточки по номеру тестового контакта |
| 6 | В журнале connectors после запуска: `коннектор запущен`; строки `max-greenapi:` при сбоях; ключи не печатаются |

## Откат

`git checkout 275cef7 && sh /opt/rf-messenger/deploy.sh </dev/null`. Миграция `005` только расширяет список видов канала; созданные каналы `max_phone` после отката будут в статусе «Этот тип канала будет доступен на следующем этапе» — удалить в виджете.
